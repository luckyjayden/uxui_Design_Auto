## 코드가 지켜야 할 경계

[개발 아키텍처](../docs/10-dev-architecture.md) 9절이 정한 것입니다. 리뷰에서
이것부터 봅니다.

| 경계 | 깨지는 모습 | 근거 |
| --- | --- | --- |
| 저장소에 쓰지 않는다 | POST 호출이나 쓰기 토큰이 생긴다 | POL-034 |
| 승인하지 않는다 | 승인 버튼이 생긴다. 승인은 PR 병합뿐이다 | POL-002 |
| 에이전트를 실행하지 않는다 | 실행 버튼이 생긴다. 1차는 세션 링크만 둔다 | FSD 7절 |
| 파일 접근은 `data/load.ts`를 거친다 | 화면이 `../../projects/...`를 직접 안다 | DEV 5.2절 |
| 항목 ID는 바뀌지 않는다 | 코드가 ID를 다시 매기거나 재사용한다 | POL-014 |

### 데이터를 읽는 방법

`src/data/load.ts`가 **유일한 통로**입니다. `import.meta.glob`으로 빌드할 때
`projects/` 아래의 JSON을 묶어 들어오므로 **실행 중에는 저장소를 읽지 않습니다.**
서버가 필요 없고 네트워크도 쓰지 않습니다.

그래서 **"읽은 시점"은 곧 빌드 시점**입니다(`READ_AT`). POL-004가 화면에 함께
보이라고 정한 값이고, 새로고침은 페이지를 다시 불러 새 빌드를 받는 것을 뜻합니다.

### 번들의 `fetch` 한 줄에 대하여

빌드 결과에 `fetch(e.href)`가 하나 있습니다. **Vite의 modulepreload 폴리필**이
자기 자산(`<link rel=modulepreload>`)을 받는 same-origin GET이고, 저장소에 쓰는
것이 아닙니다. POST·PUT·DELETE·PATCH는 0건입니다.

[MVP 수용 기준](../docs/MVP_ACCEPTANCE_CRITERIA.md)의 AC-03("빌드 결과에 네트워크
쓰기 호출이 없다")을 기계로 볼 때 이 줄에 걸리지 않게 해야 합니다. 보는 것은
**쓰기 메서드와 바깥 호스트**이지 `fetch`라는 글자가 아닙니다.

## props를 푸는 규칙

데이터 규격 4절이 정한 것입니다. props의 **키**는 React prop 이름이고(POL-026),
**값**은 그 화면 `state`의 키이거나 글자 그대로입니다.

```
값이 그 화면 state의 키면  →  그 state의 값
아니면                     →  글자 그대로
on*이 state 키를 가리키면  →  그 키를 바꾸는 콜백
```

`"onSelectArea": "selectedAreaId"`는 "누르면 `selectedAreaId`를 바꾼다"는
뜻입니다. 배열도 원소마다 같은 규칙으로 풉니다 — 화면설계서 11절이 넘긴
`["parentRefs", "childRefs"]`(state 키의 배열)와 `["디스크립션", "예외"]`
(글자 그대로의 배열) 둘 다 받습니다.

## 두 겹 state

`previewState`는 **그려진 화면의 것**이고 뷰어 자신의 state와 섞지 않습니다.
화면 파일의 `state`로 초기화합니다. 화면설계서 11절이 넘긴 자리입니다.

인터랙션의 `set`이 가리키는 키가 그 화면 `state`에 없으면 **눌러도 아무 일도
일어나지 않고** '인터랙션을 돌리지 못했습니다'를 보입니다. `set`이 `null`인
것은 바깥으로 나가거나 상태를 바꾸지 않는 것이라 누를 자리는 두되 값을
바꾸지 않습니다.

## A-2에서 설계와 부딪힌 것 셋

구현하면서 드러났습니다. **고치지 않고 적어 둡니다.** 어느 쪽을 고칠지는 사람이
정할 일입니다.

### 1. 새로고침이 실제로 다시 읽지 못합니다

`SCR-001-A01`의 디스크립션 4번이 이렇게 적었습니다.

> 누르면 지금 화면이 쓰는 파일을 **모두 다시 읽고** 읽은 시점을 지금으로 바꾼다

그런데 데이터는 `import.meta.glob`으로 **빌드할 때 묶여 들어옵니다.** 실행 중에
다시 읽을 것이 없습니다. 지금 새로고침은 **읽은 시점만 바꿉니다.**

페이지를 통째로 새로고침하는 길도 있지만 그것은 같은 영역의 예외 5번과
부딪힙니다 — *"실패하면 앞서 읽은 값과 읽은 시점을 그대로 두고 화면의 값을
비우지 않는다."* 페이지를 다시 불러오면 화면의 값이 전부 비워집니다.

길은 둘입니다.

| 길 | 내용 | 값 |
| --- | --- | --- |
| 가 | JSON을 `public/`에 두고 실행 중에 `fetch`로 읽는다 | 새로고침이 진짜가 된다. GET이라 POL-034에 걸리지 않는다. 빌드 구조가 바뀐다 |
| 나 | 설계를 고친다 — "뷰어는 페이지를 열 때만 읽는다" | 코드를 안 바꾼다. 새로고침 자리의 뜻이 약해진다 |

### 2. 검색어를 내보낼 prop이 설계에 없습니다

`SCR-001-A01`의 인터랙션이 `set: "keyword"`인데, 그 영역의 `props`에 검색어를
내보낼 자리가 없습니다. 레지스트리의 `showSearch`는 boolean 하나뿐입니다.

`onSearch`를 **제안으로 더해** 구현했습니다. POL-026은 props 키가 코드 prop
이름이어야 한다고 정하므로, 설계에 이 자리를 더하든지 다른 길을 정해야 합니다.

### 3. 저장소 주소를 넣을 자리가 없습니다

우측 액션이 "저장소 열기"인데 **GitHub 주소가 프로젝트 데이터 어디에도
없습니다.** `project.json`에도 `_meta/`에도 없습니다.

설계가 정한 대로 '연결할 곳이 없습니다'를 보이고 비활성으로 두었습니다
(예외 3번). 동작은 맞지만 **영영 그 상태입니다.** 주소를 어디에 둘지 정해야
합니다.

## 토큰

`src/tokens/tokens.css`가 레지스트리의 `spec.tokens` 이름을 CSS 변수로 받습니다.
이름은 `/`를 `-`로 바꾼 것입니다.

```
color/bg/surface  →  --color-bg-surface
```

블록 컴포넌트는 색·여백·타이포에 값을 직접 적지 않고 이 변수만 씁니다.
**값은 아직 제안입니다.** 레지스트리의 토큰은 이름만 있고 값이 없어, 실제 값은
Figma에서 와야 합니다.

## 라우팅

`HashRouter`입니다. 정적 호스팅에서 서버 설정 없이 돌아야 하기 때문입니다.
`BrowserRouter`는 새로고침할 때 서버가 모든 경로를 `index.html`로 보내 줘야 합니다.

화면 간 이동 21건은 `ia.json`의 `transitions`가 정합니다. A-0에서는 화면마다
자리만 잡아 두었고, 이동을 실제로 엮는 것은 08 Wireframe Rendering입니다.

```
├── Shell.tsx   틀. 글로벌 헤더 자리는 A-2에서 블록으로 바뀐다

```
