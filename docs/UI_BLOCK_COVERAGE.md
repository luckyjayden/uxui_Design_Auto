# UI 블록 커버리지: 영역 48개를 무엇으로 덮는가

## 1. 문서 개요

화면 영역 48개가 가리키는 블록 20종을 하나씩 보고, **어떻게 구현할지와 언제 만들지**를 정합니다. [MVP 간극 분석](MVP_GAP_ANALYSIS.md)이 센 값을 그대로 씁니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요. BLK-0020의 prop 이름과 구현 공유 방식은 확정됐고 **분류와 우선순위는 제안**입니다. |
| 대상 | 라이브러리 블록 5종, 등록 요청 15건, 확장 요청 1건 |
| 근거 | `screens/SCR-*.json`의 `block`과 `props`, 화면설계서 9절, `reference/uxui-registry-mock/` |

### 분류하는 여섯 가지

| 분류 | 뜻 |
| --- | --- |
| **재사용** | 레지스트리 블록을 그대로 씁니다. 지금은 코드가 없어 **명세대로 새로 구현**해야 하지만, 설계를 바꾸지 않습니다 |
| **Variant 확장** | 만든 컴포넌트 하나에 변형을 더해 다른 자리도 덮습니다 |
| **조합** | 이미 만든 컴포넌트 둘 이상을 합쳐 만듭니다 |
| **신규** | 같은 쓰임의 것이 없어 처음부터 만듭니다 |
| **Layout** | 블록이 아니라 다른 블록을 담는 틀로 처리합니다 |
| **MVP 제외** | 이번에 만들지 않고 자리만 둡니다 |

### 우선순위

| 순위 | 기준 | 종 |
| --- | --- | --- |
| **P0** | `SCR-005 화면설계서 뷰어`의 영역 9개를 덮는 것 | 9 |
| **P1** | 나머지 화면 여섯이 돌아가는 데 필요한 것 | 10 |
| **P2** | MVP에서 다른 것으로 대신할 수 있는 것 | 1 |

**P0를 SCR-005로 잡은 까닭**은 그 화면이 **다른 화면을 그리는 화면**이기 때문입니다. `SCR-005-A03 와이어프레임`이 화면 파일의 `areas`를 React로 그리므로, 이 아홉이 서면 **나머지 블록이 만들어지는 족족 뷰어 안에서 바로 보입니다.** 만든 것을 확인할 수단이 먼저 생깁니다.

> **DRM과 순서가 다릅니다.** [개발 로드맵](11-dev-roadmap.md)은 M3(WU-001) → M4(WU-002) → M5(WU-003, SCR-005) 순입니다. 이 문서는 SCR-005를 앞에 둡니다. 어느 순서로 갈지는 [구현 계획](IMPLEMENTATION_PLAN.md) 4절에서 둘을 견주어 적었고, 사람이 정할 일입니다.

## 2. 라이브러리 블록 5종

레지스트리에 정의가 있고 화면이 `BLK-xxxx`로 가리키는 것들입니다. **정의는 있고 코드는 없습니다.** `code.path`가 가리키는 `@uxui/core`·`@uxui/blocks`가 이 저장소에 없습니다.

| --- | --- | --- | --- | --- | --- |
| BLK-0001 | 글로벌 헤더 | 7 | 재사용 + Variant 확장 | **P0** | `BRQ-0016`으로 슬롯 둘을 더합니다 |
| BLK-0012 | 빈 상태 | 6 | 재사용 | **P0** | 레지스트리 props 4개 그대로 |
| BLK-0003 | 버튼 그룹 | 5 | 재사용 | **P0** | 레지스트리 props 3개 그대로 |

| BLK-0013 | 무한 스크롤 목록 | 1 | MVP 제외 | P2 | 아래 2.2절 |

레지스트리의 `spec`에 Figma 슬롯·variants·토큰이 적혀 있어 **구현 명세가 이미 있습니다.** 토큰은 `spec.tokens`의 이름을 CSS 변수로 그대로 받습니다(DEV 4절).

### 2.1 BLK-0020의 prop 이름은 2026-11-27에 확정됐습니다

레지스트리의 `code`가 `{"connected": false}`라 비어 있던 자리입니다. 화면설계서가 제안한 그대로 확정했습니다([결정 기록](decisions.md)).

```
tabs  activeTabId  onTabChange
```

다른 블록의 코드 prop(`logo`·`showBack`·`title`·`actions`·`showSearch`)과 같은 영문 camelCase 결이라 레지스트리에 올릴 때도 맞습니다. 쓰는 자리 셋 — `SCR-003-A02`, `SCR-004-A02`, `SCR-005-A02` — 의 `props`가 **고칠 것 없이 그대로 맞습니다.**

`reference/`는 고치지 않으므로(POL-024) 레지스트리에 code connect를 등록하는 일은 블록 담당자에게 넘깁니다.

### 2.2 BLK-0013은 이번에 만들지 않습니다

쓰는 자리가 `SCR-002-A06 열려 있는 PR 목록` 하나뿐인데, [개발 로드맵](11-dev-roadmap.md) 2절이 **"열려 있는 PR 목록의 실시간 조회"를 MVP 밖으로 미뤘습니다.** 1차는 GitHub 링크로 대신합니다(DEV 5.2절).

무한 스크롤은 다음 쪽을 불러오는 블록이라 **조회가 없으면 쓸 일이 없습니다.** 그 영역은 `BLK-0012 빈 상태`나 링크 한 줄로 대신하고, 조회를 붙일 때 되살립니다. **화면설계서는 고치지 않습니다** — 설계는 맞고 구현 범위만 좁히는 것입니다.

### 3.5 BRQ-0011은 블록이 아니라 틀입니다

`SCR-005-A03 와이어프레임`은 **다른 블록을 품어 화면 한 장을 그리는 자리**입니다. props가 `areas`·`selectedAreaId`·`onSelectArea`·`previewState`·`onPreviewStateChange`·`unrenderedMessage`·`emptyMessage`이고, 하는 일은 셋입니다.

1. 화면 파일의 `areas`를 **적힌 순서대로** 그립니다. 더하거나 빼거나 자리를 바꾸지 않습니다.
2. 블록 ID로 컴포넌트를 찾습니다. **못 찾으면 그 자리에 블록 ID와 '블록을 그리지 못했습니다'를 보이고 나머지는 그대로 그립니다.**
3. 영역의 `interactions`를 눌러 볼 수 있게 하고, `set`이 가리키는 키를 `previewState` 안에서 바꿉니다. 서버 없이 React State로만 돕니다.

**이것이 블록 ID → 컴포넌트 대응표를 들고 있는 유일한 자리**이며, 블록을 만들어 갈수록 2번의 메시지가 줄어듭니다. 그래서 **가장 먼저 만들어야 하는 것**입니다. 만든 블록을 확인할 수단이 여기서 생깁니다.

구현은 블록이라기보다 렌더러이므로, `viewer/src/blocks/` 아래가 아니라 **렌더러 계층에 둘지** 정해야 합니다(DEV 5절의 렌더러와 같은 자리로 보입니다).

### 3.6 BRQ-0009는 외부 라이브러리에 기댑니다

[개발 아키텍처](10-dev-architecture.md) 4절이 **React Flow**를 제안했습니다. 분기에 정책을 달고 연결되지 않은 분기를 강조해야 해서 노드를 React 컴포넌트로 그릴 수 있어야 하기 때문입니다.

지금 유저 플로우는 **단계 42개·연결 56개·분기 9개**입니다. 자동 배치가 필요하고 손으로 좌표를 잡을 양이 아닙니다. **P1 중 가장 비쌉니다.** `SCR-004`를 미루면 함께 미뤄집니다.

## 4. 확장 요청 BRQ-0016

| 항목 | 내용 |
| --- | --- |
| 대상 | `BLK-0001` 글로벌 헤더 2.1.0 → 2.2.0 |
| 더하는 것 | '읽은 시점' (TEXT), '새로고침' (BOOLEAN) |
| props | `readAt`, `onRefresh` |
| 쓰는 곳 | `SCR-001-A01` ~ `SCR-007-A01` 일곱 곳 |
| 분류 | **Variant 확장** |
| 순위 | **P0** (BLK-0001과 함께) |

Minor 확장이라 화면이 적어 둔 참조 범위 `^2` 안에 들어옵니다. **영역의 `block.id`는 `BLK-0001` 그대로입니다.** `BRQ-0016`으로 바꾸면 있는 블록을 없는 블록으로 잘못 적는 것이 됩니다.

POL-004가 "화면은 저장소를 읽은 시점을 함께 보이고, 다시 읽기는 새로고침으로 한다"고 정했고, 헤더 한 자리를 넓혀 일곱 장이 모두 받도록 한 것입니다.

> 다른 열다섯과 성격이 다릅니다. 열다섯은 *없는 블록을 만들어 달라*이고 이것은 *있는 블록을 넓혀 달라*입니다. [데이터 규격](08-data-spec.md) 6절에 이 구분을 적을 자리가 없어 화면설계서가 11절에 넘겼습니다.
