# 정보 구조도: AI UX 설계 자동화 시스템

## 1. 문서 개요와 ID 규칙

이 문서는 이 시스템의 화면 구조입니다. 화면 목록과 ID, 화면 사이의 이동, 그리고 화면설계서를 작성하는 작업 단위를 적습니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요. Claude가 쓴 초안입니다. |
| ID 규칙 | 화면은 STU-00, 작업 단위는 WU-000입니다. 한 번 붙인 ID는 바꾸거나 재사용하지 않습니다. |
| 선행 문서 | [유저 플로우](04-user-flow.md), [워크 플로우](05-workflow.md), [기능 정의서](03-functional-spec.md) 4절 |
| 처리용 데이터 | 아직 없습니다. `ia.json`은 [데이터 규격](08-data-spec.md) 4절의 형식을 따릅니다. |

화면 ID에 SCR이 아니라 STU를 쓰는 이유가 있습니다. 이 시스템이 만들어 내는 다른 서비스의 화면은 SCR이고, 이 시스템 자체의 화면은 STU입니다(기능 정의서 1절). 이 프로젝트는 자기 자신이 파일럿이라 두 ID가 같은 자리에 오지만, 섞지 않고 STU로 둡니다.

## 2. 화면이 놓이는 곳

웹 구동 방식 확정에 따라 사람이 쓰는 자리가 셋으로 나뉩니다(기능 정의서 4절). 이 문서가 설계하는 것은 그중 **뷰어**뿐입니다.

| 곳 | 화면을 설계하는가 | 이유 |
| --- | --- | --- |
| claude.ai/code 세션 | 아니오 | Claude Code 웹의 기본 화면을 그대로 씁니다. 맞춤 화면을 만들지 않습니다. |
| GitHub | 아니오 | PR과 파일 편집 화면을 그대로 씁니다. 승인 권한만 브랜치 보호 규칙으로 정합니다. |
| 뷰어 (UX AI Studio) | 예 | 이 문서와 [화면설계서](07-screen-spec.md)가 설계합니다. |

뷰어는 저장소의 파일을 읽기만 합니다(POL-034). 편집·승인·실행이 필요한 자리에는 세션이나 GitHub으로 가는 링크를 둡니다.

## 3. 화면 목록과 계층

뷰어 화면은 7개입니다. STU-03은 폐기했고 ID를 다시 쓰지 않습니다.

```
프로젝트 목록 (STU-01)
└─ 프로젝트 대시보드 (STU-02)
   ├─ 문서 보기 (STU-04)
   ├─ 플로우 미리보기 (STU-05)
   ├─ 화면설계서 뷰어 (STU-07)
   ├─ 변경 영향 (STU-06)
   └─ 검증 결과 (STU-08)
```

| 화면 ID | 화면 | 상위 | 하는 일 | 관련 유저 플로우 |
| --- | --- | --- | --- | --- |
| STU-01 | 프로젝트 목록 | 없음 | 프로젝트 카드와 진행 상태를 보여 준다. 들어오는 입구다. | UF-001 |
| STU-02 | 프로젝트 대시보드 | STU-01 | 요약 수치 3개, 기획 진행 단계 7개와 상태, 현재 단계 카드, 열려 있는 PR 목록 | UF-001, UF-009, UF-013 |
| STU-03 | (폐기) 프로젝트 정의서 입력 | — | GitHub의 템플릿과 파일 편집으로 옮겼습니다. | UF-002 |
| STU-04 | 문서 보기 | STU-02 | 항목 ID별 본문, 상태 배지, 참조 패널(상위·하위 항목) | UF-005 |
| STU-05 | 플로우 미리보기 | STU-02 | 유저·워크 플로우 다이어그램, 분기에 연결된 정책, 연결되지 않은 분기 강조, PNG 내보내기 | UF-005, UF-015 |
| STU-06 | 변경 영향 | STU-02 | 바뀐 항목과 변경 내용, 영향받는 산출물과 판정 | UF-016 |
| STU-07 | 화면설계서 뷰어 | STU-02 | 작업 단위 목록과 상태, 화면 목록, 동작하는 화면, 영역별 정책·디스크립션·예외, 내보내기 | UF-010, UF-011, UF-015, UF-017 |
| STU-08 | 검증 결과 | STU-02 | 검증 규칙별 결과, 누락·충돌 목록, 요구사항 반영률 | UF-014 |

## 6. 작업 단위

화면설계서는 작업 단위를 기준으로 작성합니다(POL-035). 아래는 IA Agent 자리에서 Claude가 묶은 제안이며, 사람이 이 문서를 승인해야 선택지가 됩니다(POL-037).

묶은 기준은 **사용자가 한 번에 하는 일**입니다. 메뉴 계층이 아니라 유저 플로우의 덩어리를 따랐습니다. 묶는 기준 자체는 아직 확정되지 않았습니다(POL-036).

| 작업 단위 | 이름 | 속한 화면 | 묶은 근거 | 근거가 된 플로우 |
| --- | --- | --- | --- | --- |
| WU-001 | 프로젝트와 진행 현황 | STU-01, STU-02 | 들어와서 "지금 어디까지 됐나"를 보는 한 묶음. 뷰어의 입구이고 다른 화면으로 나가는 허브다. | UF-001, UF-009, UF-013 |
| WU-002 | 문서와 플로우 보기 | STU-04, STU-05 | 생성 결과를 읽고 참조를 따라가는 한 묶음. 둘 다 항목 ID와 참조 패널을 함께 쓴다. | UF-005 |
| WU-003 | 화면설계서 보기 | STU-07 | 동작하는 화면을 렌더링하는 유일한 화면이고, 다른 화면과 구조가 가장 다르다. 혼자 둔다. | UF-010, UF-011, UF-015 |
| WU-004 | 변경과 검증 | STU-06, STU-08 | 둘 다 판정 결과 목록을 보여 주고 실패·영향 항목에서 문서로 보낸다. | UF-014, UF-016 |

모든 화면이 작업 단위 하나에만 속합니다(POL-036). 폐기된 STU-03은 어디에도 넣지 않습니다.

작성 순서는 WU-001 → WU-002 → WU-003 → WU-004를 제안합니다. 앞의 작업 단위가 공통 요소(헤더, 상태 배지, 항목 목록)를 먼저 정하면 뒤의 작업 단위가 그 블록을 재사용합니다.

## 7. 미정 사항

- [ ] 화면을 작업 단위로 묶는 기준 (POL-036). 이 문서는 유저 플로우의 덩어리를 따랐습니다.
- [ ] 공통 화면의 처리. 뷰어에는 모든 화면이 쓰는 글로벌 헤더가 있는데, 이를 따로 작업 단위로 둘지 WU-001에 넣을지. 이 문서는 WU-001에 넣었습니다.
- [ ] 뷰어를 배포할 곳. 화면 구조와는 별개지만 STU-01의 진입 경로가 여기에 달려 있습니다.
- [ ] 작업 단위 묶음과 작성 순서의 확정. Claude의 제안입니다.
- [ ] 이 문서를 `ia.json`으로 옮기는 일. 유저 플로우의 화면 배정(`screen`)과 함께 합니다.
