# 화면설계서: AI UX 설계 자동화 시스템

## 1. 문서 개요

이 문서는 뷰어(UX AI Studio)의 화면 설계입니다. 화면마다 구성, 인터랙션, 디스크립션, 예외 상황을 적습니다.

이 시스템이 만들어 내는 화면설계서와 같은 형식으로 썼습니다. 그대로 `screens/STU-00.json`이 되고 뷰어의 첫 시험 데이터가 됩니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요. Claude가 쓴 초안입니다. |
| 선행 문서 | [정보 구조도](06-information-architecture.md) 0.1.0 |
| 형식 | [데이터 규격](08-data-spec.md) 4절의 `screens/SCR-000.json`. 화면 ID는 STU, 영역 ID는 `STU-00-A00`입니다. |
| 이번 판의 범위 | **WU-001 프로젝트와 진행 현황**(STU-01, STU-02)만 썼습니다. |

### 왜 하나만 썼는가

화면설계서는 작업 단위를 기준으로 작성합니다(POL-035, POL-037). 작업 단위를 하나 골라 쓰고, 사람이 그 작업 단위를 승인한 뒤 다음 작업 단위로 넘어갑니다(POL-038). 네 작업 단위를 한 번에 쓰면 이 방식을 문서로 정해 놓고 스스로 어기는 셈이 됩니다.

| 작업 단위 | 화면 | 상태 |
| --- | --- | --- |
| WU-001 프로젝트와 진행 현황 | STU-01, STU-02 | 이 문서 2절. 검토 필요 |
| WU-002 문서와 플로우 보기 | STU-04, STU-05 | 대기 |
| WU-003 화면설계서 보기 | STU-07 | 대기 |
| WU-004 변경과 검증 | STU-06, STU-08 | 대기 |

## 2. WU-001 프로젝트와 진행 현황

### STU-01 프로젝트 목록

뷰어에 들어오는 입구입니다. 저장소의 `projects/` 아래 폴더를 읽어 카드로 보여 줍니다.

```json
{
  "id": "STU-01",
  "title": "프로젝트 목록",
  "refs": ["UF-001"],
  "state": { "keyword": "", "projects": [] },
  "areas": ["STU-01-A01", "STU-01-A02", "STU-01-A03", "STU-01-A04"]
}
```

| 영역 | 이름 | 블록 | props | 요구사항 | 정책 |
| --- | --- | --- | --- | --- | --- |
| STU-01-A01 | 글로벌 헤더 | BLK-0001 `^2` | `logo`, `title`, `showSearch`, `actions` | REQ-024 | POL-034 |
| STU-01-A02 | 프로젝트 카드 목록 | BRQ-0001 (등록 요청) | `items`, `onSelect` | REQ-002 | POL-013 |
| STU-01-A03 | 빈 상태 | BLK-0012 `^1` | `illustration`, `title`, `description`, `action` | REQ-002 | POL-013 |
| STU-01-A04 | 새 프로젝트 보내기 | BLK-0003 `^2` | `primaryAction`, `secondaryAction` | REQ-001 | POL-034 |

**디스크립션**

- STU-01-A01: 검색은 프로젝트 이름만 거릅니다. 저장소를 넘나드는 검색은 하지 않습니다.
- STU-01-A02: 카드에 프로젝트 이름, 기획 진행 단계 7개 중 완료 수, 마지막 커밋 날짜를 보여 줍니다. `_meta/status.json`을 읽어 만듭니다.
- STU-01-A03: 프로젝트가 하나도 없을 때만 A02 대신 보입니다.
- STU-01-A04: 주 버튼은 claude.ai/code 세션을 새 탭으로 엽니다. 뷰어가 프로젝트를 만들지 않습니다.

**인터랙션**

| 트리거 | 바꾸는 state | 결과 |
| --- | --- | --- |
| 검색어 입력 | `keyword` | A02의 카드 목록을 거릅니다. |
| 프로젝트 카드 누름 | 없음 | STU-02로 이동합니다. |
| 새 프로젝트 누름 | 없음 | 세션을 새 탭으로 엽니다. 뷰어는 그대로 둡니다. |

**예외 상황**

| 상황 | 화면 |
| --- | --- |
| `projects/` 아래에 폴더가 없다 | A03 빈 상태. 새 프로젝트 버튼을 함께 보입니다. |
| 검색 결과가 없다 | A03 빈 상태. 문구를 "검색 결과가 없습니다"로 바꿉니다. |
| `status.json`을 읽을 수 없다 | 카드의 진행 상태 자리에 "상태를 읽지 못했습니다"를 보이고 카드 자체는 보입니다. 뷰어는 파일을 고치지 않습니다(POL-034). |

### STU-02 프로젝트 대시보드

한 프로젝트의 지금 상태를 한 화면에서 봅니다. 다른 화면으로 나가는 허브입니다.

```json
{
  "id": "STU-02",
  "title": "프로젝트 대시보드",
  "refs": ["UF-001", "UF-009", "UF-013"],
  "state": { "selectedStage": null, "pullRequests": [] },
  "areas": ["STU-02-A01", "STU-02-A02", "STU-02-A03", "STU-02-A04", "STU-02-A05"]
}
```

| 영역 | 이름 | 블록 | props | 요구사항 | 정책 |
| --- | --- | --- | --- | --- | --- |
| STU-02-A01 | 글로벌 헤더 | BLK-0001 `^2` | `logo`, `title`, `showBack`, `actions` | REQ-024 | POL-034 |
| STU-02-A02 | 요약 수치 | BRQ-0002 (등록 요청) | `metrics` | REQ-002 | POL-005 |
| STU-02-A03 | 기획 진행 단계 | BRQ-0003 (등록 요청) | `steps`, `currentIndex`, `onSelect` | REQ-002 | POL-001, POL-004 |
| STU-02-A04 | 현재 단계 카드 | BRQ-0004 (등록 요청) | `summary`, `links` | REQ-002, REQ-009 | POL-034 |
| STU-02-A05 | 열려 있는 PR | BLK-0013 `^2` | `renderItem`, `loading`, `endMessage` | REQ-010 | POL-031 |

**디스크립션**

- STU-02-A02: 수치 세 개의 정의는 기능 정의서 4절을 따릅니다. 완료 단계는 문서가 모두 승인 상태인 단계 수, 검토 단계는 검토 필요나 수정 필요 문서가 있는 단계 수, 생성 문서는 만들어진 문서 파일 수입니다.
- STU-02-A03: 단계는 프로젝트 정의서, 요구사항 정의서, 정책서, 유저·워크 플로우, 정보 구조도, 화면설계서, 최종 검증의 7개입니다. 단계마다 문서 상태 다섯 가지 중 하나를 배지로 보입니다.
- STU-02-A03: 화면설계서 단계는 작업 단위마다 상태를 따로 갖습니다(POL-038). 단계 배지는 가장 뒤처진 작업 단위의 상태를 보이고, 펼치면 작업 단위별 상태가 나옵니다.
- STU-02-A04: 고른 단계의 생성 요약, 근거 건수, 발견된 문제를 보입니다. 실행·수정 요청은 세션 링크로, 검토·승인은 PR 링크로 보냅니다. 뷰어 안에 버튼을 두지 않습니다.
- STU-02-A05: 이 프로젝트 경로를 건드리는 열린 PR만 보입니다. 제목, 올린 사람, 대상 문서를 함께 보입니다.

**인터랙션**

| 트리거 | 바꾸는 state | 결과 |
| --- | --- | --- |
| 진행 단계 누름 | `selectedStage` | A04의 내용이 그 단계로 바뀝니다. |
| 화면설계서 단계 펼침 | `selectedStage` | 작업 단위별 상태 목록을 폅니다. |
| A04의 문서 보기 누름 | 없음 | STU-04로 이동합니다. 플로우 단계면 STU-05, 화면설계서 단계면 STU-07입니다. |
| A04의 실행·수정 요청 누름 | 없음 | 세션을 새 탭으로 엽니다. |
| A05의 PR 누름 | 없음 | GitHub PR을 새 탭으로 엽니다. |

**예외 상황**

| 상황 | 화면 |
| --- | --- |
| 아직 아무 단계도 실행되지 않았다 | A03의 모든 단계가 대기. A04는 "프로젝트 정의서를 확정하면 시작합니다"와 GitHub 링크를 보입니다(POL-007). |
| 선행 문서가 승인 전이라 다음 단계를 승인할 수 없다 | A04에 "선행 문서가 승인되어야 승인할 수 있습니다"를 보입니다(POL-004). |
| 승인된 항목이 바뀌어 영향 분석이 필요하다 | A02 위에 변경 알림 줄을 띄우고 STU-06으로 보냅니다(POL-018). |
| 실행이 사용량 한도로 중단됐다 | A04에 중단 시각과 "한도가 초기화되면 이어서 실행하세요"를 보입니다(POL-029). |
| 열린 PR이 없다 | A05에 끝 안내만 보입니다. 빈 상태 블록을 쓰지 않습니다. |

## 3. 화면에서 쓰는 UI 블록

WU-001이 쓰는 블록입니다. 라이브러리는 Core 가이드, 표준 블록 순으로 찾았습니다(POL-022).

| 블록 | 이름 | 등급 | 버전 범위 | 쓴 곳 | 고른 근거 |
| --- | --- | --- | --- | --- | --- |
| BLK-0001 | 글로벌 헤더 | core | `^2` | STU-01-A01, STU-02-A01 | "서비스 전 화면 공통". 뷰어의 모든 화면이 씁니다. |
| BLK-0003 | 버튼 그룹 | core | `^2` | STU-01-A04 | 주 행동이 하나(새 프로젝트)이고 선택지가 둘을 넘지 않습니다. |
| BLK-0012 | 빈 상태 | standard | `^1` | STU-01-A03 | "검색 결과 없음, 첫 사용". 두 경우 모두 해당합니다. |
| BLK-0013 | 무한 스크롤 목록 | standard | `^2` | STU-02-A05 | "알림 목록"에 가까운 쓰임입니다. 정렬이 중요한 정산 목록이 아니라 "쓰지 않을 때"에 걸리지 않습니다. |

### 등록 요청한 블록

맞는 블록이 라이브러리에 없어 프로젝트 블록으로 만들고 등록 요청을 남겼습니다(POL-024, FN-503). 표준 블록 폴더에 직접 쓰지 않았습니다.

| 요청 | 블록 이름 | 쓴 곳 | 왜 필요한가 |
| --- | --- | --- | --- |
| BRQ-0001 | 프로젝트 카드 목록 | STU-01-A02 | 상품 카드 리스트(BLK-0017)는 가격·할인·배지 슬롯이라 진행 상태를 담지 못합니다. |
| BRQ-0002 | 요약 수치 | STU-02-A02 | 수치 몇 개를 나란히 보이는 블록이 라이브러리에 없습니다. |
| BRQ-0003 | 진행 단계 표시 | STU-02-A03 | 배송 추적 타임라인(BLK-0023)이 비슷하나 local 등급이고 배송 전용입니다. |
| BRQ-0004 | 단계 요약 카드 | STU-02-A04 | 요약과 바깥 링크를 함께 담는 블록이 없습니다. |

등록 요청 중인 블록을 쓴 영역은 검증 보고서에 따로 표시됩니다(QA-07). 승인 전에는 표준 블록으로 취급하지 않습니다.

**이 네 건이 드러낸 것.** 블록 레지스트리의 목업 25개는 커머스 서비스용이고, 이 시스템의 뷰어는 문서를 다루는 도구입니다. 겹치는 블록이 공통 요소(헤더, 버튼, 빈 상태, 목록)뿐이라 작업 단위 하나에서 벌써 등록 요청이 네 건 나왔습니다.

**2026-11-26에 정했습니다. 등록 요청을 쌓으면서 진행합니다.** 뷰어용 블록을 먼저 채우는 길도, 파일럿 대상을 커머스 쪽으로 바꾸는 길도 택하지 않습니다. 맞는 블록이 없으면 프로젝트 블록으로 만들고 등록 요청을 남긴 채 다음 작업 단위로 넘어갑니다(POL-024). 검증 보고서에 미등록 블록 참조가 쌓이는 것은 실패가 아니라 예정된 결과입니다(QA-07).

파일럿이 끝나면 그때 쌓인 등록 요청이 뷰어용 블록 묶음의 목록이 됩니다. 뷰어에 쓸 수 있는 기존 블록은 공통 요소 아홉 개뿐입니다. BLK-0001 글로벌 헤더, BLK-0003 버튼 그룹, BLK-0004 입력 폼 필드, BLK-0005 다이얼로그, BLK-0006 토스트, BLK-0012 빈 상태, BLK-0013 무한 스크롤 목록, BLK-0016 검색 자동완성, BLK-0020 탭 콘텐츠입니다.

## 4. 미정 사항

- [x] 뷰어용 UI 블록이 라이브러리에 없는 문제. 2026-11-26에 등록 요청을 쌓으면서 진행하기로 정했습니다. 3절과 [결정 기록](decisions.md)을 보십시오.
- [x] 코드 연결이 없는 블록의 와이어프레임용 React 컴포넌트를 누가 만드는지(POL-026). 2026-11-26에 확정했습니다. 따로 만들지 않고 **코드 연결이 없는 채로 진행합니다.** Figma에서 화면을 그리는 일은 별도로 진행하고, 블록 레지스트리가 완성되면 블록 생성자가 블록 링크를 등록합니다.
- [x] 등록 요청 ID의 번호 매기기. 2026-11-26에 확정했습니다. 같은 블록이면 이 문서가 붙인 **BRQ-0001~0004를 그대로 다시 쓰고, 새 블록만 BRQ-0005부터** 붙입니다. 번호를 새로 매기면 ID를 바꾸거나 재사용하지 않는다는 규칙(POL-014)과 어긋납니다. [결정 기록](decisions.md)을 보십시오.
- [ ] WU-002~004의 화면설계서. WU-001을 승인한 뒤에 씁니다(POL-037, POL-038).
- [ ] 이 문서를 `screens/STU-00.json`으로 옮기는 일. 뷰어의 첫 시험 데이터가 됩니다.
- [ ] 화면 영역 ID에 STU를 쓰는 것(`STU-01-A01`). 데이터 규격은 `SCR-000-A00`으로 적혀 있습니다(제안).
