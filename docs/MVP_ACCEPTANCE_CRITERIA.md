# MVP 수용 기준: 무엇이 되면 끝난 것인가

## 1. 문서 개요

[구현 계획](IMPLEMENTATION_PLAN.md)의 작업이 끝났는지 **사람이 가릴 수 있게** 기준을 적습니다. "거의 된 것 같다"로 끝나지 않게 하는 것이 목적입니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요. **전부 제안입니다.** |
| 기준의 성격 | 하나하나가 **참이거나 거짓**입니다. 정도를 매기지 않습니다 |
| 확인하는 주체 | 스크립트가 보는 것과 사람이 봐야 하는 것을 갈라 적었습니다 |
| MVP의 정의 | [DRM](11-dev-roadmap.md) 2절을 그대로 씁니다. 이 문서는 그것을 확인 가능한 문장으로 옮깁니다 |

### MVP의 선

> 파일럿 한 건이 프로젝트 정의서에서 화면설계서까지 완주하는 데 필요한 최소 코드 — [DRM](11-dev-roadmap.md) 2절

**앞쪽 절반은 2026-11-27에 이미 끝났습니다.** 파이프라인 01~06이 완주해 문서 일곱 종이 승인됐습니다. 남은 것은 **뒤쪽 절반 — 그 문서대로 뷰어를 만들고, 뷰어가 그 문서를 보여 주는 것**입니다.

## 2. 묶음 하나 — 뷰어가 선다 (AC-01 ~ AC-06)

| ID | 기준 | 확인 |
| --- | --- | --- |
| AC-01 | `npm run build`가 통과하고 정적 파일이 나온다 | 스크립트 |
| AC-02 | 서버 없이 정적 파일만으로 뷰어가 열린다 | 스크립트 |
| AC-03 | 빌드 결과에 **네트워크 쓰기 호출이 없다** (POL-034) | 스크립트 |
| AC-04 | 화면에 **승인하는 자리가 없다** (POL-002) | 사람 |
| AC-05 | 화면에 **에이전트를 실행하는 버튼이 없다** (FSD 7절) | 사람 |
| AC-06 | 화면이 파일 경로를 직접 알지 않고 `data/load.ts`를 거친다 (DEV 9절) | 스크립트 |

**AC-03 ~ AC-05가 MVP의 성격을 정합니다.** 뷰어는 읽기만 합니다. 이 셋이 깨지면 다른 기준을 다 채워도 받지 않습니다.

## 3. 묶음 둘 — 설계대로 그린다 (AC-07 ~ AC-13)

| ID | 기준 | 확인 |
| --- | --- | --- |
| AC-07 | 화면 일곱 장이 모두 열린다 | 스크립트 |
| AC-08 | 영역이 화면 파일의 `areas` **순서 그대로** 그려진다 (POL-014) | 스크립트 |
| AC-09 | 화면마다 그려진 자리의 수가 `areas` 수와 같다. **그리지 못한 자리도 셉니다** | 스크립트 |
| AC-10 | `ia.json`의 `transitions` **21건이 모두** 걸려 있고 끊긴 길이 없다 | 스크립트 |
| AC-11 | 영역의 `props` 키가 컴포넌트의 prop 이름과 **글자 그대로** 같다 (POL-026) | 스크립트 |
| AC-12 | `interactions`의 `set`이 모두 그 화면 `state`의 키이고, 눌러서 값이 바뀐다 | 스크립트 + 사람 |
| AC-13 | 영역 48개 가운데 **P0·P1 블록이 덮는 47개가 그려진다** | 스크립트 |

**AC-09가 숨김을 막습니다.** 그리지 못한 영역을 건너뛰면 수가 줄어 통과하지 못합니다. `SCR-005-A03`의 예외가 요구하는 것과 같습니다 — 못 그린 자리에 **블록 ID와 안내를 보이고 나머지는 그대로 그립니다.**

**AC-13의 47은 `BLK-0013`을 뺀 수입니다.** `SCR-002-A06`은 MVP 밖이라([COV](UI_BLOCK_COVERAGE.md) 2.2절) 그 자리는 빈 상태나 링크로 대신합니다.

## 4. 묶음 셋 — 뷰어가 자기 설계를 보여 준다 (AC-14 ~ AC-18)

파일럿 대상이 이 시스템 자신이므로, **뷰어가 자기를 만든 문서를 보여 줄 수 있어야 합니다.**

| ID | 기준 | 확인 |
| --- | --- | --- |
| AC-14 | `SCR-003`이 문서 일곱 종의 항목을 보이고, 항목의 출처(`ai`/`human`)를 구분한다 | 사람 |
| AC-15 | `SCR-005`가 화면 일곱 장을 그리고, 영역을 고르면 디스크립션·예외·요구사항·정책·쓴 블록이 나온다 | 사람 |
| AC-16 | `SCR-005`의 와이어프레임에서 **인터랙션을 눌러 볼 수 있다.** 서버 없이 React State로 돈다 | 사람 |
| AC-17 | `SCR-006`이 `validation.json`의 규칙 일곱과 판정을 보인다 | 사람 |
| AC-18 | 참조를 눌러 **다른 문서의 그 항목으로 옮겨 간다** (REQ-006) | 사람 |

**AC-15가 이 시스템의 핵심입니다.** 화면설계서 JSON을 사람이 읽는 화면으로 바꾸는 것이 이 도구의 존재 이유입니다.

## 5. 묶음 넷 — 예외가 재현된다 (AC-19 ~ AC-21)

| ID | 기준 | 확인 |
| --- | --- | --- |
| AC-19 | 영역의 `exceptions`마다 **그 상황을 화면에서 만들 수 있다** | 사람 |
| AC-20 | 파일이 없거나 JSON이 깨졌을 때 화면이 죽지 않고 그 자리에만 안내가 나온다 | 스크립트 + 사람 |
| AC-21 | 등록 요청 중인 블록을 쓴 영역에 **그렇다는 표시가 붙는다** (POL-016, QA-07) | 사람 |

**AC-19가 가장 손이 많이 갑니다.** 영역 48개에 예외가 붙어 있고 정책×영역 짝이 193개입니다. 전부를 사람이 하나씩 열어 볼 수는 없으므로, [PV2](PIPELINE_V2.md) 7절의 `review`가 **재현 목록을 차려 주는 것**이 전제입니다.

## 6. 묶음 다섯 — 파이프라인 07~10 (AC-22 ~ AC-26)

**갈래 B를 만들기로 했을 때만 해당합니다.** 블록을 사람이 손으로 만든다면 이 묶음은 비워 둡니다.

| ID | 기준 | 확인 |
| --- | --- | --- |
| AC-22 | 코드에도 자물쇠가 걸린다. 다른 세션의 쓰기가 막힌다 | `test_guard.py` |
| AC-23 | `check_gate.py`가 07~10의 시작·완료 조건을 판정한다 | `test_gate.py` |
| AC-24 | `implement`를 불러 블록 하나가 끝까지 만들어진다 | 사람 |
| AC-25 | `impl-qa`가 규칙 여덟을 판정하고 실패에 `owner_agent`를 지정한다 | 사람 |
| AC-26 | 실패한 규칙의 담당 에이전트를 다시 불러 닫힌다 (POL-008) | 사람 |

**AC-24가 갈래 B의 실제 증명입니다.** 01~06에서 `screen` 에이전트가 작업 단위 넷을 돈 것과 같은 모양이 되어야 합니다.

## 7. 확인하는 방법

### 스크립트가 보는 것

| 무엇 | 어떻게 |
| --- | --- |
| AC-01·02·07 | 빌드와 정적 서빙 |
| AC-03·06 | 빌드 결과에서 쓰기 호출과 직접 경로 접근을 찾습니다 |
| AC-08·09·10·11·13 | [PV2](PIPELINE_V2.md) 6절의 `impl-validation.json`. 규칙 IQ-01 ~ IQ-08이 이 기준들과 짝입니다 |
| AC-20 | 일부러 깨뜨린 파일을 넣고 화면이 사는지 봅니다 |
| AC-22·23 | `test_guard.py`, `test_gate.py` |

### 사람이 봐야 하는 것

| 무엇 | 왜 |
| --- | --- |
| AC-04·05 | "승인 버튼이 없다"를 기계가 가리기 어렵습니다. 화면을 봐야 압니다 |
| AC-14 ~ AC-18 | 보이는 것이 맞는지는 읽어 봐야 압니다 |
| AC-19·21 | 재현 목록을 따라 눌러 봅니다 |
| AC-24 ~ AC-26 | 에이전트를 실제로 불러야 압니다 |

## 8. MVP 밖 — 이것이 안 돼도 받습니다

[DRM](11-dev-roadmap.md) 2절이 미룬 것에 이 문서의 것을 더합니다.

| 무엇 | 왜 |
| --- | --- |
| Figma 내보내기 | 결정 기록 2026-11-25 |
| 블록 레지스트리의 저장소화와 커넥터 | 1차는 뷰어가 쓰는 블록만 만듭니다 (DEV 8절) |
| 열려 있는 PR 목록의 실시간 조회 | GitHub 링크로 대신합니다 (`BLK-0013`, `SCR-002-A06`) |
| 뷰어의 실행 버튼 | 세션 링크만 둡니다 |
| 부분 재생성, 승인 해제 | 영향 분석까지만 합니다 |
| PNG·PPTX 내보내기의 품질 | **나오는 것까지**가 MVP입니다. 장표 구성의 다듬음은 밖입니다 |
| 다이어그램 자동 배치의 보기 좋음 | 단계 42개가 겹치지 않고 읽히면 받습니다 |
| 반응형과 작은 화면 | 데스크톱 한 폭으로 받습니다 |

**경계가 흐린 것 둘**을 적어 둡니다. PNG·PPTX와 다이어그램은 "되긴 되는데 보기 나쁜" 상태가 나올 수 있습니다. 받을지 말지를 미리 정해 두지 않으면 끝에서 다툽니다.

## 9. 받는 절차

1. 스크립트가 보는 기준을 전부 돌립니다. 하나라도 실패면 **사람을 부르지 않습니다.**
2. [PV2](PIPELINE_V2.md) 7절의 `review`가 사람이 걸어 볼 길과 예외 재현 목록을 차립니다.
3. 사람이 `PROTOTYPE-REVIEW.md`에 본 것과 판단을 적습니다.
4. 통과하면 **사람이 PR을 병합해 승인합니다**(POL-002). 에이전트가 승인하지 않습니다.

**고칠 것이 설계에 있으면 05로 돌아갑니다.** 그러면 `SB`가 `검토 필요`로 내려가고 06부터 다시 돕니다. 그려 보고 나서야 드러나는 것이 있어 이 길을 열어 둡니다.

| 8절의 흐린 경계 둘 | 내보내기 품질과 다이어그램 보기 좋음을 어디서 자를지 |

| AC-13의 47 | `BLK-0013` 자리를 무엇으로 대신할지가 정해져야 셈이 맞습니다 |
| 수용 기준의 ID 접두어 | `AC-00`으로 제안했습니다. [데이터 규격](08-data-spec.md) 3절의 ID 규칙에 넣을지 |
