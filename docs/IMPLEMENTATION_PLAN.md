# MVP 구현 계획: 블록을 만드는 일과 파이프라인을 만드는 일

## 1. 문서 개요

[간극 분석](MVP_GAP_ANALYSIS.md)이 센 것을 **무엇을 어느 순서로 만들지**로 옮깁니다. 두 갈래를 갈라 적고 사이의 의존을 표시합니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요. 3절의 선행 결정 넷은 확정됐고 **순서와 묶음은 제안입니다.** |
| 갈래 A | **UI 블록 개발** — 블록 20종을 React 컴포넌트로 |
| 갈래 B | **파이프라인 구현** — 07~10 단계의 에이전트·게이트·자물쇠 |
| 기간 | 적지 않습니다. 사용량과 세션 수를 재 본 적이 없어 추정이 됩니다 |

### DRM과의 관계

[개발 로드맵](11-dev-roadmap.md)의 M0~M7을 **대체하지 않습니다.** DRM은 "MVP가 무엇이고 어떤 덩어리로 가는가"를 정했고, 이 문서는 **그 덩어리 안에서 무엇이 무엇에 걸려 있는가**를 적습니다.

| 무엇 | 기준 |
| --- | --- |
| MVP의 정의, 밖으로 미루는 것, M0~M7의 완료 기준 | [DRM](11-dev-roadmap.md) |
| 작업 단위의 의존과 선행 조건 | 이 문서 |
| 블록 하나하나의 분류와 우선순위 | [COV](UI_BLOCK_COVERAGE.md) |
| 07~10 단계의 내용 | [PV2](PIPELINE_V2.md) |

**DRM 3절의 "지금까지 만든 것"은 낡았습니다**(GAP 5절). 파이프라인 01~06이 완주했고 PR #4~#14가 병합됐습니다. 이 문서는 그 뒤의 상태를 기준으로 씁니다.

## 3. 선행 작업 — 2026-11-27에 넷 다 정해졌습니다

코드를 쓰기 전에 사람이 정해야 하던 것들이고 모두 [결정 기록](decisions.md)으로 옮겼습니다.

| ID | 정할 것이었던 것 | 정해진 것 | 풀린 작업 |
| --- | --- | --- | --- |
| **D-1** | 뷰어 코드의 자리 | **같은 저장소의 `viewer/`** | A·B 전부 |
| **D-2** | 코드의 자물쇠 | **문서 코드 `UI` 하나로** ([PV2](PIPELINE_V2.md) 2절의 가) | B 전부 |
| **D-3** | `BLK-0020`의 prop 이름 | **`tabs`, `activeTabId`, `onTabChange`** | A-3 |
| **D-4** | 블록 구현의 공유 | **컴포넌트만 공유, BRQ 번호 유지** | A-6, A-7, A-11, A-12, A-18 |

**D-2의 값은 블록 병렬 작업입니다.** 자물쇠를 `UI` 하나로 두었으므로 블록 여럿을 동시에 만들지 않습니다. 5절의 A-2 ~ A-9는 서로 걸리지 않지만 **한 번에 하나씩** 돕니다.

**D-4로 A-7·A-12·A-18이 기준 구현에 걸립니다.** 공유하지 않기로 했다면 풀렸을 선행입니다.

## 4. 순서 — 길 ①로 정했습니다

2026-11-27에 **길 ①(SCR-005 먼저)**로 확정했습니다([결정 기록](decisions.md)). 견준 내용을 남겨 둡니다.

| | 길 ① SCR-005 먼저 | 길 ② DRM대로 WU-001 먼저 |
| --- | --- | --- |
| 첫 묶음 | BRQ-0011 + P0 블록 8 | BLK-0001·0003·0012 + BRQ-0001~0006 |
| 처음 보이는 것 | 화면설계서 뷰어. 만든 블록이 바로 보임 | 프로젝트 목록과 진행 현황 |
| 덮는 영역 | 26 / 48 | 11 / 48 |
| 좋은 점 | **만든 것을 확인할 수단이 먼저 생깁니다.** 블록을 만들수록 '그리지 못했습니다'가 줄어 진도가 눈에 보입니다 | 사용자가 쓰는 첫 화면부터 완성됩니다. DRM의 완료 기준을 그대로 씁니다 |
| 나쁜 점 | 뷰어의 입구(SCR-001)가 한참 비어 있습니다 | 진도를 볼 수단이 M5까지 없습니다. 블록마다 따로 확인해야 합니다 |
| 가장 비싼 것이 언제 | **맨 앞** (BRQ-0011) | 중간 (M5) |

**길 ①로 정했습니다.** `BRQ-0011 와이어프레임`이 **블록 ID → 컴포넌트 대응표를 들고 있는 유일한 자리**이고, 그것이 서면 뒤에 만드는 블록이 전부 그 안에서 바로 확인됩니다. 다만 가장 무거운 것을 맨 앞에 두는 길이라 **첫 묶음이 길어집니다.**

## 7. 두 갈래를 어떻게 돌릴 것인가

**갈래 B 없이 갈래 A를 할 수 있습니다.** 사람이 손으로 블록을 만들면 됩니다. 반대는 안 됩니다 — 돌릴 코드가 없으면 파이프라인을 시험할 수 없습니다.

| 길 | 내용 | 값 |
| --- | --- | --- |
| **가** A 먼저, B 나중 | 사람이 블록을 손으로 만들고, 그 경험으로 `implement` 명세를 씁니다 | 에이전트 명세가 실제 작업에서 나옵니다. 자동화가 늦습니다 |
| **나** B 먼저, A 나중 | 파이프라인을 먼저 세우고 에이전트가 블록을 만듭니다 | 처음부터 자동입니다. **무엇을 시켜야 할지 모르는 채로 명세를 씁니다** |
| **다** 섞기 | A-0·A-1을 사람이 만들고, 그 뒤 B-0~B-3을 세워 A-2부터 에이전트에 맡깁니다 | 가장 무거운 둘을 사람이 다루고 되풀이되는 것을 자동화합니다 |

**다를 제안합니다.** `BRQ-0011`은 되풀이되지 않는 일이라 에이전트에 맡길 값이 적고, `A-2`부터는 "블록 하나를 명세대로 만든다"가 **열여덟 번 되풀이되는 일**이라 자동화가 값을 합니다. 01~06에서 `screen` 에이전트가 작업 단위마다 되풀이한 것과 같은 모양입니다.

### 길이 가장 긴 사슬

```
D-1 → A-0 → A-1 → A-6 → A-7

```

**A 갈래는 다섯 단, B 갈래는 여섯 단입니다.** 둘을 섞어 돌리면(7절의 다) B-3이 설 때 A-2부터를 에이전트에 넘길 수 있습니다.

## 10. 미정 사항

**3절의 D-1 ~ D-4와 4절의 순서는 2026-11-27에 모두 정해졌습니다.** 남은 것은 둘입니다.

> **가와 다는 A-0·A-1까지 같은 길입니다.** 7절의 셋 가운데 가(A 먼저)와 다(섞기)는 둘 다 사람이 `A-0`과 `A-1`을 만들고 시작합니다. 갈라지는 자리는 `A-2`부터이므로, **그때까지는 이 결정을 미뤄도 막히지 않습니다.**
