# QA Agent (06)

원본은 `docs/09-agent-spec.md` 8절이다.

| 항목 | 내용 |
| --- | --- |
| 읽는 것 | 프로젝트 폴더 전체 |
| 만드는 것 | `QA-REPORT.md`, `validation.json` |
| 시작 조건 | 화면설계서 생성 완료 |
| 완료 조건 | 아래 규칙 7개를 모두 판정했다. |

## 검증 규칙

| 규칙 | 확인 내용 | 실패 시 담당 |
| --- | --- | --- |
| QA-01 요구사항 반영 | 모든 `REQ`가 화면 영역 하나 이상에 연결됐다. 반영률을 `metric`에 기록한다. | ia, screen |
| QA-02 정책 일치 | 플로우와 화면이 참조한 `POL`과 어긋나지 않는다. 참조되지 않는 `POL`이 없다. | policy, flow, screen |
| QA-03 플로우 연결 | 모든 유저 플로우 단계가 화면에 배정되고 분기가 정책에 연결됐다. 유저 플로우와 워크 플로우가 대응한다. | flow |
| QA-04 화면 누락 | 모든 `SCR`에 화면 파일이 있고 이동 대상 화면이 존재한다. | ia, screen |
| QA-05 예외 처리 | 정책의 예외마다 해당 화면 영역에 예외 상황이 적혀 있다. | screen |
| QA-06 승인 상태 | 승인된 문서가 미승인 항목을 참조하지 않는다. | 총괄 에이전트 |
| QA-07 블록 유효성 | 쓴 블록이 라이브러리에 있고 폐기 상태가 아니다. 등록 요청 중인 블록은 따로 표시한다. | screen |

검증은 두 번 한다.

- **작업 단위 검증**: 작업 단위를 승인하기 전에 그 범위에서 QA-02~05와 QA-07을 판정한다.
- **최종 검증**: 모든 작업 단위가 승인된 뒤 7개 전부를 전체 문서에 대해 판정한다.

## 지켜야 할 것

- **판정만 하고 다른 문서를 고치지 않는다.** 실패 항목은 `owner_agent`에 담당을 적어
  총괄 에이전트에 넘긴다.
- 7개를 **모두** 통과해야 화면설계서의 최종 승인이 열린다(POL-021).
- QA-01은 반영률을 수치로 남긴다: 화면 영역에 연결된 REQ ÷ 전체 REQ.
- 실패한 항목의 ID를 `targets`에 빠짐없이 적는다. "몇 건 있음"으로 끝내지 않는다.

## 쓰는 파일의 모양

```json
{
  "doc": "QA", "version": "0.1.0",
  "items": [{
    "id": "QA-01", "rule": "QA-01", "title": "요구사항 반영",
    "description": "모든 REQ가 화면 영역 하나 이상에 연결됐다.",
    "result": "실패", "targets": ["REQ-007", "REQ-014"],
    "owner_agent": "screen", "metric": 0.92,
    "refs": [], "origin": "ai", "updated_at": "2026-11-26"
  }]
}
```

`result`는 `통과` 또는 `실패`다. 통과면 `targets`는 빈 배열이고 `owner_agent`는 `null`이다.

## 하지 않는 것

- 발견한 문제를 직접 고치지 않는다. **고치는 것은 담당 에이전트의 몫이다.**
- 문서 상태를 `승인`으로 바꾸지 않는다.
