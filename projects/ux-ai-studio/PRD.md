# 요구사항 정의서: UX AI Studio

> **Requirements Agent가 만든 초안입니다. 사람의 승인 전입니다.**
> 승인은 사람이 PR을 병합할 때만 일어납니다(POL-002).

## 1. 문서 개요

이 문서는 [프로젝트 정의서](PROJECT.md)의 목적·목표·범위·제약을 요구사항으로 푼 것입니다.
요구사항은 지어내지 않고 정의서에서만 뽑았으며, 항목마다 어느 절에서 나왔는지 출처를 적었습니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요 |
| ID 규칙 | `REQ-000`. 1번부터 차례로 붙이고 비는 번호를 두지 않습니다. 한 번 붙인 ID는 바꾸거나 재사용하지 않습니다. |
| 유형 | 기능, 비기능, 제약 |
| 우선순위 | 높음, 보통, 낮음. 정의서에 명시된 값이 없어 **제안**입니다. 정의서가 포함 범위로 적은 것을 높음, 내보내기와 보조 확인을 보통, 범위를 한정하는 제약을 낮음으로 두었습니다. |
| 참조 | `refs`에 그 요구사항이 받드는 `GOAL-00`을 적습니다. |
| 처리용 데이터 | [requirements.json](requirements.json) |

요구사항은 21개입니다. 기능 14개, 비기능 1개, 제약 6개입니다.

사용자 유형은 정의서 3절을 따릅니다. 주 사용자는 기획자이고, 개발·QA 담당자와 UI 블록 담당자가 함께 씁니다.

## 4. 범위 밖

정의서 4절의 제외 범위입니다. 요구사항으로 두지 않았고, 범위를 지키는 쪽만 REQ-015·REQ-016·REQ-021로 적었습니다.

| 항목 | 처리 |
| --- | --- |
| 문서 편집과 승인 | GitHub PR에서 합니다. 뷰어는 링크만 둡니다(REQ-004, REQ-016). |
| 에이전트 실행 | claude.ai/code 세션에서 합니다. 뷰어는 링크만 둡니다(REQ-004). |
| 저장소에 쓰는 모든 동작 | 뷰어는 읽기 전용입니다(REQ-015). |
| Figma 연결 | 검증된 화면을 나중에 세션의 커넥터로 잇습니다(REQ-021). |

## 6. 총괄 에이전트에 넘기는 사항

정의서에 없어 요구사항으로 만들지 않은 것들입니다. 필요하면 정의서를 보완해 주십시오.

| 사항 | 왜 필요한가 |
| --- | --- |
| 우선순위 기준 | 정의서에 목표별 우선순위가 없어 이 문서의 우선순위는 제안입니다. |
| 뷰어가 읽는 저장소의 범위와 접근 권한 | 뷰어가 어느 저장소의 어느 경로를 읽는지, 누가 볼 수 있는지가 정의서에 없습니다. |
| 저장소의 변경이 화면에 반영되는 시점 | 실시간인지 새로고침인지가 정의서에 없어 REQ-020의 수용 기준을 시점까지 적지 못했습니다. |
| PPTX의 장표 구성 | 어떤 단위로 장표를 나누는지가 정의서에 없습니다. REQ-012의 수용 기준을 확인 가능한 선까지만 적었습니다. |
