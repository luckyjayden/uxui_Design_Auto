# 프로젝트 정의서: UX AI Studio

> **초안입니다. 사람이 검토하고 고쳐야 합니다.** 다 되면 `project.json`의 `confirmed`를
> `true`로 바꾸십시오. 그때까지 Requirements Agent는 시작하지 않습니다(POL-007).

## 1. 무엇을 만드는가

UX AI Studio는 AI UX 설계 자동화 시스템이 만든 산출물을 기획자가 브라우저에서 보는 뷰어입니다.

기획자는 터미널을 쓰지 않습니다. 단계 실행과 수정 요청은 claude.ai/code 세션에서, 문서 편집과
승인은 GitHub PR에서 합니다. 그 둘로는 볼 수 없는 것 — 프로젝트가 지금 어디까지 왔는지, 항목이
서로 무엇을 참조하는지, 플로우가 어떻게 생겼는지, 화면설계서가 실제로 어떻게 동작하는지 — 을
한곳에서 보여 주는 것이 이 뷰어입니다.

뷰어는 저장소의 파일을 **읽기만 합니다.** 편집·승인·실행이 필요한 자리에는 세션이나 GitHub으로
가는 링크를 둡니다.

이 프로젝트는 시스템의 파일럿이기도 합니다. 시스템이 자기 자신의 기획 문서를 만들어 봄으로써
파이프라인이 끝까지 도는지 확인합니다(2026-11-25 결정).

## 2. 목표

| ID | 목표 | 설명 |
| --- | --- | --- |
| GOAL-01 | 진행 상황을 한곳에서 본다 | 프로젝트가 7개 단계 중 어디까지 왔고 무엇이 사람을 기다리는지 한 화면에서 안다. |
| GOAL-02 | 문서 사이의 참조를 따라간다 | 항목 하나를 골라 그것이 참조하는 상위 항목과 그것을 참조하는 하위 항목으로 오간다. |
| GOAL-03 | 화면설계서를 동작하는 화면으로 본다 | 화면설계서 JSON을 실제로 그려 보고, 영역마다 걸린 정책·디스크립션·예외를 함께 읽는다. |
| GOAL-04 | 산출물을 밖으로 낸다 | 유저 플로우를 PNG로, 화면설계서를 PPTX로 내보내 다른 도구에서 쓴다. |
| GOAL-05 | 검증 결과와 변경 영향을 확인한다 | 무엇이 누락됐는지, 무엇이 바뀌어 어디를 고쳐야 하는지 목록으로 본다. |

## 3. 사용자

| 유형 | 설명 |
| --- | --- |
| 기획자 | 주 사용자. 생성 결과를 읽고 검토하며, 어느 작업 단위를 다음에 쓸지 고른다. |
| 개발·QA 담당자 | 승인된 화면설계서를 넘겨받아 개발과 테스트에 쓴다. |
| UI 블록 담당자 | 화면이 어떤 블록을 썼는지, 등록 요청이 무엇인지 확인한다. |

## 4. 범위

### 포함

- 프로젝트 목록과 진행 현황
- 문서 보기와 참조 관계 패널
- 유저 플로우·워크 플로우 다이어그램과 PNG 내보내기
- 화면설계서 렌더링과 PPTX 내보내기
- 검증 결과와 변경 영향 목록

### 제외

- 문서 편집과 승인. GitHub PR에서 합니다.
- 에이전트 실행. claude.ai/code 세션에서 합니다.
- 저장소에 쓰는 모든 동작. 뷰어는 읽기 전용입니다.
- Figma 연결. 검증된 화면을 나중에 세션의 커넥터로 잇습니다.

## 5. 제약

- 뷰어는 저장소에 쓰지 않습니다. 쓰기 경로를 두지 않습니다.
- 사람의 승인은 PR 병합으로만 일어납니다. 뷰어에 승인 버튼을 두지 않습니다.
- 와이어프레임은 React로 그리고 인터랙션은 React State로 구현합니다.
- 화면에 쓰는 UI 블록은 블록 레지스트리의 블록을 ID와 Major 버전 범위로 참조합니다.
- 사용자는 10인 미만이고 사내 도구 범위입니다.
