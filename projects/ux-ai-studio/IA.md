# 정보 구조도: UX AI Studio

> **IA Agent가 만든 초안입니다. 사람의 승인 전입니다.**
> 승인은 사람이 PR을 병합할 때만 일어납니다(POL-002). 6절의 작업 단위는 **제안**이며,
> 이 문서가 승인되어야 화면설계서 작성의 선택지가 됩니다(POL-037).

## 1. 문서 개요

이 문서는 뷰어의 화면 목록과 화면 사이의 이동, 그리고 화면설계서를 작성하는 작업 단위를 적습니다.
[유저 플로우](USER-FLOW.md)와 [워크 플로우](WORKFLOW.md)에서 뽑았으며, 플로우에 나오지 않는
화면은 만들지 않았습니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요 |
| ID 규칙 | 화면은 `SCR-000`, 작업 단위는 `WU-000`. 1번부터 차례로 붙이고 비는 번호를 두지 않습니다. 한 번 붙인 ID는 바꾸거나 재사용하지 않습니다. |
| 선행 문서 | [유저 플로우](USER-FLOW.md) 0.1.0, [워크 플로우](WORKFLOW.md) 0.1.0, [요구사항 정의서](PRD.md) |
| 화면 수 | 7개 |
| 작업 단위 수 | 4개 |
| 처리용 데이터 | [ia.json](ia.json) |

화면을 뽑은 기준은 하나입니다. **유저 플로우의 단계가 실제로 일어나는 자리**입니다. 단계 35개 중
화면이 필요한 22개(진입 3, 선택 15, 완료 4)를 모아 보니 7개 자리로 모였습니다(5절).

이 프로젝트는 시스템의 파일럿이라 저장소의 [정보 구조도](../../docs/06-information-architecture.md)가
같은 뷰어를 `STU-00`으로 이미 설계해 두었습니다. 화면의 덩어리는 그것과 같고, ID 체계만 다릅니다.
설계 대상 서비스의 화면은 `SCR`, 이 시스템 자체의 화면은 `STU`입니다([데이터 규격](../../docs/08-data-spec.md) 3절).

### 메뉴에 대하여

`menu`와 `group`은 **화면을 묶어 부르는 이름일 뿐 새로 만든 내비게이션 계층이 아닙니다.**
플로우에 없는 메뉴 계층을 지어내지 않았습니다. 모든 화면은 프로젝트 목록(SCR-001) →
진행 현황(SCR-002)을 거쳐 들어갑니다(POL-008, POL-006). 진행 현황이 유일한 허브입니다.

```
프로젝트 목록 (SCR-001)
└─ 프로젝트 진행 현황 (SCR-002)        ← 산출물을 고르는 허브
   ├─ 문서 보기 (SCR-003)
   ├─ 플로우 미리보기 (SCR-004)
   ├─ 화면설계서 뷰어 (SCR-005)
   ├─ 검증 결과 (SCR-006)
   └─ 변경 영향 (SCR-007)
```

## 3. 화면 간 이동

`transitions`에 적은 이동입니다. 모두 대상 화면이 실재합니다(QA-04). 플로우의 `next`와
어긋나지 않습니다(QA-03). 근거 칸이 '제안'인 둘은 플로우에 단계가 없어 새로 적은 것입니다.

| --- | --- | --- | --- |
| SCR-001 | SCR-002 | 프로젝트 카드를 누른다 | UF-005 → UF-006 |
| SCR-002 | SCR-001 | 상단의 프로젝트 이름을 눌러 목록으로 돌아간다 | 제안 (POL-008) |
| SCR-002 | SCR-003 | 문서 단계 카드의 '문서 보기'를 누른다 | UF-011 문서 → UF-012 |
| SCR-002 | SCR-004 | 플로우 단계 카드를 누른다 | UF-011 플로우 → UF-015 |
| SCR-002 | SCR-005 | 화면설계서 단계 카드를 누른다 | UF-011 화면설계서 → UF-019 |
| SCR-002 | SCR-006 | 검증 단계 카드를 누른다 | UF-011 검증 → UF-024 |
| SCR-002 | SCR-007 | 변경 영향 알림을 누른다 | UF-011 변경 → UF-027 |

| SCR-003 | SCR-005 | 참조 패널의 화면(SCR) 항목을 누른다 | UF-013, UF-014 연결됨 |
| SCR-004 | SCR-003 | 분기에 걸린 정책 ID를 누른다 | UF-016 |

## 5. 유저 플로우 단계의 화면 배정

`user-flow.json`의 `screen`을 채웠습니다. **IA Agent가 자기 문서 밖에 쓰는 유일한 자리이며,
`screen` 말고 다른 필드는 건드리지 않았습니다.**

`step_type`이 진입·선택·완료인 22개는 모두 채웠습니다. 분기 9개와 이탈 4개는 `null`로 두었습니다.
분기는 화면에 그려지는 자리가 아니라 다음 화면을 가르는 판정이고, 이탈은 뷰어 밖이거나 다른
화면의 빈 상태로 나타나기 때문입니다.

## 6. 작업 단위 (제안)

화면설계서는 작업 단위를 기준으로 작성합니다(POL-035). 아래는 **제안**이며 사람이 이 문서를
승인해야 선택지가 됩니다(POL-037).

묶은 기준은 **사용자가 한 번에 하는 일**입니다. 메뉴 계층이 아니라 유저 플로우의 덩어리를
따랐습니다. 모든 화면이 작업 단위 하나에만 속합니다(POL-036).

| 작업 단위 | 이름 | 속한 화면 | 플로우 구간 | 묶은 근거 |
| --- | --- | --- | --- | --- |
| WU-001 | **프로젝트와 진행 현황** | SCR-001, SCR-002 | UF-001~UF-011 | 들어와서 '지금 어디까지 됐나'를 보는 한 묶음. 세 사용자 유형이 모두 이 길로 들어온다(POL-008). 뷰어의 입구이자 다른 모든 화면으로 나가는 허브다. |
| WU-002 | **문서와 플로우 보기** | SCR-003, SCR-004 | UF-012~UF-018 | 생성 결과를 읽고 참조를 따라가는 한 묶음. 두 화면이 서로를 오가며(정책 ID → 문서 항목, 참조 패널 → 다이어그램) 같은 '항목 ID와 참조 이동' 요소를 공유한다. 따로 설계하면 어긋나기 쉽다. |
| WU-003 | **화면설계서 보기** | SCR-005 | UF-019~UF-023 | 화면설계서 JSON을 동작하는 화면으로 그리는 유일한 화면이라 혼자 둔다. 영역·블록·인터랙션이라는 구조가 다른 화면과 전혀 다르고, 블록 참조와 등록 요청 표시(POL-016)도 여기에만 있다. |
| WU-004 | **검증과 변경 영향** | SCR-006, SCR-007 | UF-024~UF-027, UF-031 | 둘 다 '판정 결과 목록을 보고 고칠 곳으로 옮겨 간다'는 같은 일을 한다. 검증 결과에서 변경 영향으로 바로 넘어간다(UF-025, UF-026). |

### 작성 순서 제안

```
WU-001 → WU-002 → WU-003 → WU-004
```

앞의 작업 단위가 공통 요소를 먼저 정하면 뒤가 그대로 재사용합니다.

| 순서 | 작업 단위 | 여기서 정해져 뒤가 쓰는 것 |
| --- | --- | --- |
| 1 | WU-001 | 글로벌 헤더, 문서 상태 배지(POL-005의 다섯 값), 단계 카드, 바깥 링크(세션·GitHub)의 모양 |
| 2 | WU-002 | 항목 목록과 항목 ID 배지, 참조 패널, 끊긴 참조 표시, 내보내기 버튼과 실패 처리 |
| 3 | WU-003 | 영역 선택과 나란히 보이는 패널. WU-002의 항목 ID 배지와 내보내기를 받아 쓴다. |
| 4 | WU-004 | 판정 목록. 앞선 세 작업 단위의 화면으로 보내는 쪽이라 마지막이다. |

## 7. 총괄 에이전트에 넘기는 사항

새로 정한 것과 정하지 못한 것입니다. **제안**으로만 적습니다.

| 사항 | 지금 어떻게 두었는가 | 왜 확정이 필요한가 |
| --- | --- | --- |
| 공통 화면의 처리 | 모든 화면이 쓰는 글로벌 헤더를 따로 떼지 않고 WU-001에 넣었습니다 | 작업 단위마다 헤더를 다시 그리면 어긋납니다. 공통 작업 단위를 둘지 정해야 합니다(POL-036 미정). |
| 진행 현황으로 돌아가는 공통 경로 | SCR-003~SCR-005, SCR-007에서 진행 현황으로 돌아가는 이동을 `transitions`에 넣지 않았습니다 | 플로우에 그 단계가 없습니다. 헤더가 맡는다면 WU-001에서 한 번만 정의하면 됩니다. |
| SCR-002 → SCR-001 되돌아가기 | 3절에 제안으로 넣었습니다 | 플로우에 단계가 없습니다. 프로젝트를 바꿔 보는 길이 필요한지 확인해야 합니다. |
| SCR-007 → SCR-003 이동 | 3절에 제안으로 넣었습니다(POL-010) | UF-027의 `next`는 완료(UF-031)로만 갑니다. 영향받는 항목을 눌러 문서로 갈 수 있어야 하는지가 정책에 없습니다. |
| 사용자 유형별 첫 화면 | UF-001~003을 모두 SCR-001에 배정했습니다 | 유저 플로우 9절이 넘긴 사항과 같습니다. 담당자마다 첫 화면이 다르면 SCR-001의 설계가 갈립니다. |
