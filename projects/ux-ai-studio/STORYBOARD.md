# 화면설계서: UX AI Studio

> **Screen Agent가 만든 초안입니다. 사람의 승인 전입니다.**
> 승인은 사람이 PR을 병합할 때만 일어납니다(POL-002, 시스템 규칙). 이 판은 **WU-001 프로젝트와
> 진행 현황**만 담습니다. 다른 작업 단위의 화면(SCR-003~SCR-007)은 만들지 않았습니다(POL-037).

## 1. 문서 개요

이 문서는 작업 단위 WU-001에 속한 화면 두 장의 설계입니다. 화면마다 영역을 나누고, 영역마다
UI 블록·요구사항·정책·디스크립션·인터랙션·예외를 연결했습니다.

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요 |
| 작업 단위 | WU-001 프로젝트와 진행 현황 |
| 화면 | SCR-001 프로젝트 목록(영역 4개), SCR-002 프로젝트 진행 현황(영역 7개) |
| 선행 문서 | [정보 구조도](IA.md) 0.1.0, [정책서](POLICY.md), [요구사항 정의서](PRD.md), [유저 플로우](USER-FLOW.md), [워크 플로우](WORKFLOW.md) |
| 처리용 데이터 | [screens/SCR-001.json](screens/SCR-001.json), [screens/SCR-002.json](screens/SCR-002.json) |
| 블록 라이브러리 | `reference/uxui-registry-mock/blocks/` (읽기만 했습니다) |

화면의 덩어리와 영역 구성은 저장소의 [화면설계서](../../docs/07-screen-spec.md)가 같은 뷰어를
`STU-01`, `STU-02`로 설계해 둔 것을 근거로 삼았습니다. 다만 거기에 적힌 정책 ID는 **이 시스템
자체의 정책**이고, 이 문서가 연결한 정책 ID는 **이 프로젝트의 [정책서](POLICY.md)(POL-001~021)**
입니다. 두 체계가 번호만 같고 내용이 달라, 영역마다 프로젝트 정책서를 다시 읽고 연결했습니다.

### props 표기 규칙

`props`의 키는 블록의 React 컴포넌트 prop 이름을 그대로 씁니다(POL-026, 시스템 규칙). 한글 슬롯
이름은 쓰지 않습니다. 값은 이렇게 적었습니다.

| 값의 모양 | 뜻 | 예 |
| --- | --- | --- |
| 문자열·불리언·숫자 | 화면에 그대로 보이는 값 | `"title": "프로젝트"`, `"showSearch": true` |
| state 키 이름 문자열 | 그 화면 `state`의 값에서 온다 | `"items": "projects"` |
| state 키 이름 문자열(콜백 prop) | 눌렀을 때 그 state 키를 바꾼다 | `"onSelect": "selectedProjectId"` |

## 2. SCR-001 프로젝트 목록

뷰어의 입구입니다. 저장소의 `projects/` 아래 폴더를 읽어 카드로 보여 주고, 카드를 누르면
진행 현황(SCR-002)으로 갑니다.

```json
{
  "id": "SCR-001",
  "refs": ["UF-001", "UF-002", "UF-003", "UF-004", "UF-005", "UF-033", "WF-001~005", "WF-033"],
  "state": { "keyword": "", "projects": [], "selectedProjectId": null }
}
```

| 영역 | 이름 | 블록 | props | 요구사항 | 정책 |
| --- | --- | --- | --- | --- | --- |
| SCR-001-A01 | 글로벌 헤더 | BLK-0001 `^2` | `logo`, `title`, `showBack`, `showSearch`, `actions` | REQ-001, REQ-020 | POL-004, POL-001 |
| SCR-001-A02 | 프로젝트 카드 목록 | BRQ-0001 `^0` (등록 요청) | `items`, `onSelect`, `keyword` | REQ-001, REQ-002, REQ-020 | POL-008, POL-005, POL-004 |
| SCR-001-A03 | 빈 상태 | BLK-0012 `^1` | `illustration`, `title`, `description`, `action` | REQ-001, REQ-019 | POL-008, POL-020 |
| SCR-001-A04 | 바깥으로 나가는 버튼 | BLK-0003 `^2` | `primaryAction`, `secondaryAction`, `disabled` | REQ-004, REQ-015 | POL-003, POL-001 |

**디스크립션에서 짚을 것**

- A01: 입구라 뒤로가기를 두지 않습니다. 검색은 이미 읽어 둔 프로젝트의 **이름만** 거릅니다.
- A02: 카드의 모든 값은 `_meta/status.json`에서 읽습니다. 진행 상태 배지는 POL-005의 다섯 값만
  씁니다. **이 배지의 모양을 여기서 정하고 SCR-002와 뒤의 작업 단위가 그대로 받아 씁니다.**
- A03: A02를 대신해 보입니다. 둘이 같이 보이지 않습니다. 권한이 없어 비어 보이는 경우와 폴더가
  정말 없는 경우를 문구로 구분합니다.
- A04: 주 버튼은 claude.ai/code 세션을, 보조 버튼은 GitHub 저장소를 새 탭으로 엽니다. 뷰어는
  프로젝트를 만들지 않습니다.

**인터랙션**

| 영역 | 트리거 | 바꾸는 state | 결과 |
| --- | --- | --- | --- |
| A01 | 검색어를 입력한다 | `keyword` | A02의 카드를 이름으로 거릅니다. 결과가 없으면 A03이 보입니다. |
| A01 | 우측 액션을 누른다 | 없음 | GitHub 저장소를 새 탭으로 엽니다. |
| A02 | 프로젝트 카드를 누른다 | `selectedProjectId` | SCR-002로 갑니다. |
| A02 | 검색어가 바뀐다 | `keyword` | 이름이 검색어를 품은 카드만 남습니다. |
| A03 | 다음 행동 버튼을 누른다 | 없음 | GitHub 저장소를 새 탭으로 엽니다. |
| A04 | 주 버튼 / 보조 버튼을 누른다 | 없음 | 세션 / GitHub을 새 탭으로 엽니다. |

**예외 상황**

정책에 적힌 예외를 영역의 `exceptions`에 그대로 옮겼습니다(QA-05). 아래는 그 밖에 이 화면에서
더 적은 것입니다.

| 상황 | 화면 | 근거 |
| --- | --- | --- |
| `_meta/status.json`을 읽지 못했다 | 카드 자체는 보이고 진행 상태 자리에만 '읽지 못했습니다'와 경로를 보입니다 | POL-004, UF-035 |
| 검색 결과가 없다 | A03의 제목을 '검색 결과가 없습니다'로 바꾸고 검색어를 지우는 안내를 보입니다 | BLK-0012의 '검색 결과 없음' 변형 |
| 볼 수 있는 프로젝트가 없다 | A03만 보이고 다른 화면으로 가지 않습니다 | POL-008, POL-020, UF-033 |

## 3. SCR-002 프로젝트 진행 현황

한 프로젝트의 지금 상태를 한 화면에서 봅니다. 읽을 산출물을 고르는 허브입니다.

```json
{
  "id": "SCR-002",
  "refs": ["UF-006~UF-011", "UF-034", "UF-035", "WF-006~WF-011", "WF-034", "WF-035"],
  "state": {
    "stages": [], "selectedStage": null, "expandedStage": null,
    "expandedNotice": false, "pullRequests": [], "changeNotice": null
  }
}
```

| 영역 | 이름 | 블록 | props | 요구사항 | 정책 |
| --- | --- | --- | --- | --- | --- |
| SCR-002-A01 | 글로벌 헤더 | BLK-0001 `^2` | `logo`, `title`, `showBack`, `showSearch`, `actions` | REQ-002, REQ-020 | POL-004, POL-001 |
| SCR-002-A02 | 사람을 기다리는 일 알림 줄 | BRQ-0005 `^0` (등록 요청) | `tone`, `title`, `description`, `actionLabel`, `onAction` | REQ-003, REQ-004 | POL-007, POL-003, POL-002 |
| SCR-002-A03 | 요약 수치 | BRQ-0002 `^0` (등록 요청) | `metrics`, `columns` | REQ-002, REQ-020 | POL-005, POL-004 |
| SCR-002-A04 | 일곱 단계 진행 표시 | BRQ-0003 `^0` (등록 요청) | `steps`, `currentIndex`, `onSelect`, `expandedId` | REQ-002, REQ-003, REQ-005 | POL-006, POL-005, POL-007 |
| SCR-002-A05 | 고른 단계 요약 카드 | BRQ-0004 `^0` (등록 요청) | `summary`, `status`, `links`, `emptyMessage` | REQ-005, REQ-004, REQ-020 | POL-004, POL-003, POL-002 |
| SCR-002-A06 | 열려 있는 PR 목록 | BLK-0013 `^2` | `renderItem`, `loading`, `endMessage`, `showScrollTop` | REQ-004, REQ-016 | POL-002, POL-003 |
| SCR-002-A07 | 변경 영향 알림 줄 | BRQ-0005 `^0` (등록 요청) | `tone`, `title`, `description`, `actionLabel`, `onAction` | REQ-014, REQ-020 | POL-019, POL-004 |

**디스크립션에서 짚을 것**

- A02: 확정 대기·승인 대기·선택 대기를 한 줄로 먼저 보입니다. 둘 이상이면 앞선 단계의 것 하나를
  먼저 보이고 나머지는 펼쳐서 봅니다(POL-007). 승인 버튼이나 실행 버튼을 뷰어에 두지 않습니다.
- A03: 수치 셋(끝난 단계, 검토 중 단계, 만들어진 문서)은 모두 `_meta/status.json`과 폴더의 파일
  목록에서 **센** 값입니다. 비율이나 예상 완료일처럼 저장소에 없는 값은 보이지 않습니다(POL-004).
- A04: 단계 일곱의 순서를 바꾸지 않습니다. 화면설계서 단계는 작업 단위마다 상태를 따로 가지며,
  배지는 가장 뒤처진 작업 단위의 상태를 보이고 펼치면 작업 단위별 상태가 나옵니다.
- A05: '문서 보기'가 어느 화면으로 갈지는 **문서 코드**로 정합니다(WF-011). 문서는 SCR-003,
  플로우는 SCR-004, 화면설계서는 SCR-005, 검증은 SCR-006입니다.
- A06: 이 프로젝트 폴더를 건드리는 열린 PR만 보입니다. 승인은 GitHub에서 합니다.
- A07: `_meta/changes.json`에 승인된 항목의 변경이 있으면 요약 수치 위에 한 줄로 보이고 SCR-007로
  보냅니다. 변경 기록이 없으면 '변경이 없습니다'로 흐리게 보이고 누를 수 없습니다.

**인터랙션**

| 영역 | 트리거 | 바꾸는 state | 결과 |
| --- | --- | --- | --- |
| A01 | 뒤로가기·프로젝트 이름을 누른다 | 없음 | SCR-001로 돌아갑니다. |
| A02 | 알림 줄의 링크를 누른다 | 없음 | 승인 대기면 PR을, 확정·실행 대기면 세션을 새 탭으로 엽니다. |
| A02 | '나머지 보기'를 누른다 | `expandedNotice` | 나머지 기다리는 일의 목록을 폅니다. |
| A03 | 수치 하나를 누른다 | `selectedStage` | 그 수치에 든 첫 단계를 골라 A05를 바꿉니다. |
| A04 | 단계를 누른다 | `selectedStage` | A05의 내용이 그 단계로 바뀝니다. |
| A04 | 화면설계서 단계를 펼친다 | `expandedStage` | 작업 단위별 상태 목록을 폅니다. |
| A05 | '문서 보기'를 누른다 | 없음 | 문서 코드에 맞는 화면으로 갑니다. |
| A05 | '실행·수정 요청' / 'PR 보기'를 누른다 | 없음 | 세션 / GitHub PR을 새 탭으로 엽니다. |
| A05 | 다른 단계를 고른다 | `selectedStage` | 카드 내용이 바뀝니다. |
| A06 | PR 항목을 누른다 | 없음 | GitHub PR을 새 탭으로 엽니다. |
| A06 | 목록 끝까지 스크롤한다 | `pullRequests` | 다음 쪽을 이어 붙입니다. 더 없으면 끝 안내를 보입니다. |
| A07 | 알림 줄을 누른다 | `changeNotice` | 변경 영향(SCR-007)으로 갑니다. |

**예외 상황**

정책의 예외를 영역마다 그대로 옮겼습니다. 그 밖에 더 적은 것은 넷입니다.

| 상황 | 화면 | 근거 |
| --- | --- | --- |
| 기다리는 것이 하나도 없다 | A02를 보이지 않고 A03부터 보입니다 | POL-007 |
| 아직 아무 단계도 실행되지 않았다 | 일곱 단계가 모두 '대기'로 보이고 A05는 안내만 보입니다 | POL-005, POL-006 |
| 고른 단계의 파일이 아직 없다 | A05 본문에 '비어 있음'을 보이고 '문서 보기'를 누를 수 없게 둡니다 | POL-003, POL-004, UF-034 |
| 열린 PR이 하나도 없다 | A06에 끝 안내만 보입니다. 빈 상태 블록을 쓰지 않습니다 | BLK-0013의 '끝' 변형 |

## 4. 화면에서 쓰는 UI 블록

Core 가이드, 표준 블록 순으로 찾았습니다(POL-022, 시스템 규칙). 고른 근거는 블록의 "쓰는 상황"과
"쓰지 않을 때"입니다. 쓴 블록 넷은 모두 `guidance._source`가 `human`이고 `pending_ai_draft`가
`false`라 근거로 쓸 수 있습니다. 폐기된 블록은 쓰지 않았습니다.

| 블록 | 이름 | 등급 | 라이브러리 버전 | 참조 범위 | 쓴 곳 | 고른 근거 |
| --- | --- | --- | --- | --- | --- | --- |
| BLK-0001 | 글로벌 헤더 | core | 2.1.0 | `^2` | SCR-001-A01, SCR-002-A01 | 쓰는 상황이 "서비스 전 화면 공통". 뷰어의 모든 화면이 씁니다. 쓰지 않을 때인 전체 화면 미디어 뷰어가 아닙니다. |
| BLK-0003 | 버튼 그룹 | core | 2.1.1 | `^2` | SCR-001-A04 | 선택지가 둘이라 "좌보조·우주 배치"에 맞습니다. 주 행동을 셋 이상으로 늘리지 않습니다. |
| BLK-0012 | 빈 상태 | standard | 1.2.1 | `^1` | SCR-001-A03 | 쓰는 상황의 "검색 결과 없음"과 "첫 사용"에 모두 해당합니다. 로딩 중에는 쓰지 않습니다. |
| BLK-0013 | 무한 스크롤 목록 | standard | 2.0.0 | `^2` | SCR-002-A06 | 쓰는 상황의 "알림 목록"에 가깝습니다. 쓰지 않을 때인 "정렬 순서가 중요한 결제·정산 내역"이 아닙니다. |

### 등록 요청한 블록

맞는 블록이 라이브러리에 없어 프로젝트 블록으로 만들고 등록 요청을 남겼습니다(POL-024, 시스템
규칙). `reference/` 아래의 표준 블록 폴더에는 쓰지 않았습니다.

| 요청 | 블록 이름 | 쓴 곳 | props (React prop 이름) | 왜 라이브러리의 블록으로 안 되는가 |
| --- | --- | --- | --- | --- |
| BRQ-0001 | 프로젝트 카드 목록 | SCR-001-A02 | `items`, `onSelect`, `keyword` | 상품 카드 리스트(BLK-0017)의 prop이 `price`, `discountRate`, `wishlisted`라 진행 단계 수와 상태 배지를 담지 못합니다. |
| BRQ-0002 | 요약 수치 | SCR-002-A03 | `metrics`, `columns` | 수치 몇 개를 나란히 보이는 블록이 라이브러리에 없습니다. |
| BRQ-0003 | 진행 단계 표시 | SCR-002-A04 | `steps`, `currentIndex`, `onSelect`, `expandedId` | 배송 추적 타임라인(BLK-0023)이 모양은 비슷하나 local 등급이고 쓰는 상황이 "주문 상세, 배송 조회"입니다. |
| BRQ-0004 | 단계 요약 카드 | SCR-002-A05 | `summary`, `status`, `links`, `emptyMessage` | 요약과 바깥 링크(세션·GitHub)를 함께 담는 블록이 없습니다. |
| BRQ-0005 | 알림 줄 | SCR-002-A02, SCR-002-A07 | `tone`, `title`, `description`, `actionLabel`, `onAction` | **새로 낸 요청입니다.** 토스트(BLK-0006)는 "사용자가 행동해야 하는 오류 안내에는 쓰지 않는다"가 쓰지 않을 때이고 잠깐 떴다 사라집니다. 다이얼로그(BLK-0005)는 되돌릴 수 없는 행동 직전에 쓰는 블록입니다. 계속 보이는 인라인 안내 줄이 라이브러리에 없습니다. |

BRQ-0001~0004는 [저장소의 화면설계서](../../docs/07-screen-spec.md)가 같은 블록에 이미 붙인
번호를 그대로 다시 썼습니다(2026-11-26 결정). 새 블록인 알림 줄만 BRQ-0005로 이어 붙였습니다.

알림 줄은 **한 블록을 두 영역이 함께 씁니다.** 기다리는 일 줄(A02)과 변경 영향 줄(A07)은
`tone`과 문구만 다르고 구조가 같아 블록을 둘로 나누지 않았습니다.

등록 요청 중인 블록을 쓴 영역은 검증 보고서에 따로 표시됩니다(QA-07). 승인 전에는 표준 블록으로
취급하지 않습니다. 코드 연결이 없는 채로 둡니다. 와이어프레임용 React 컴포넌트를 따로 만들지
않고, 블록 레지스트리가 완성되면 블록 생성자가 블록 링크를 등록합니다(2026-11-26 결정).

### 블록 참조가 11개 영역 중 7개에서 등록 요청인 것에 대하여

실패가 아니라 예정된 결과입니다. 블록 레지스트리의 목업 25개는 커머스 서비스용이고 이 뷰어는
문서를 다루는 도구라, 겹치는 블록이 공통 요소(헤더, 버튼, 빈 상태, 목록)뿐입니다. 작업 단위
하나에서 등록 요청이 다섯 건 쌓였고, 파일럿이 끝나면 이 목록이 뷰어용 블록 묶음의 명세가 됩니다.
