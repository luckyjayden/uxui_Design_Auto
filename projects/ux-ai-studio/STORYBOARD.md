# 화면설계서: UX AI Studio

> **Screen Agent가 만든 초안입니다. 사람의 승인 전입니다.**
> 승인은 사람이 PR을 병합할 때만 일어납니다(POL-002, 시스템 규칙). 이 판은 **WU-001 프로젝트와
> 진행 현황**, **WU-002 문서와 플로우 보기**, **WU-003 화면설계서 보기**를 담습니다. 남은 작업
> 단위의 화면(SCR-006, SCR-007)은 만들지 않았습니다(POL-037).

## 1. 문서 개요

이 문서는 작업 단위 WU-001, WU-002, WU-003에 속한 화면 다섯 장의 설계입니다. 화면마다 영역을 나누고,
영역마다 UI 블록·요구사항·정책·디스크립션·인터랙션·예외를 연결했습니다. 작업 단위는 한 번에 하나씩
쓰며, 앞선 작업 단위가 정한 공통 요소를 뒤가 그대로 받아 씁니다(정보 구조도 6절).

| 항목 | 내용 |
| --- | --- |
| 상태 | 검토 필요 |
| 작업 단위 | WU-001 프로젝트와 진행 현황(2·3절), WU-002 문서와 플로우 보기(4·5절), WU-003 화면설계서 보기(6절) |
| 화면 | SCR-001 프로젝트 목록(영역 4개), SCR-002 프로젝트 진행 현황(영역 7개), SCR-003 문서 보기(영역 6개), SCR-004 플로우 미리보기(영역 7개), SCR-005 화면설계서 뷰어(영역 9개) |
| 선행 문서 | [정보 구조도](IA.md) 0.1.0, [정책서](POLICY.md), [요구사항 정의서](PRD.md), [유저 플로우](USER-FLOW.md), [워크 플로우](WORKFLOW.md) |
| 처리용 데이터 | [screens/SCR-001.json](screens/SCR-001.json), [screens/SCR-002.json](screens/SCR-002.json), [screens/SCR-003.json](screens/SCR-003.json), [screens/SCR-004.json](screens/SCR-004.json), [screens/SCR-005.json](screens/SCR-005.json) |
| 블록 라이브러리 | `reference/uxui-registry-mock/blocks/` (읽기만 했습니다) |

화면의 덩어리와 영역 구성은 저장소의 [화면설계서](../../docs/07-screen-spec.md)가 같은 뷰어를
`STU-01`, `STU-02`로 설계해 둔 것을 근거로 삼았습니다. 다만 거기에 적힌 정책 ID는 **이 시스템
자체의 정책**이고, 이 문서가 연결한 정책 ID는 **이 프로젝트의 [정책서](POLICY.md)(POL-001~021)**
입니다. 두 체계가 번호만 같고 내용이 달라, 영역마다 프로젝트 정책서를 다시 읽고 연결했습니다.

WU-002의 화면 둘(SCR-003, SCR-004)은 저장소의 화면설계서에 대응하는 화면이 없습니다. 그래서
[정보 구조도](IA.md) 2·3절의 화면과 이동, [유저 플로우](USER-FLOW.md) UF-012~UF-018,
[워크 플로우](WORKFLOW.md) WF-012~WF-018만 근거로 삼았고, 공통 요소(글로벌 헤더, 상태 배지,
바깥 링크 버튼, 빈 상태)는 WU-001에서 정한 것을 그대로 받아 썼습니다.

WU-003의 화면 하나(SCR-005)도 마찬가지로 저장소의 화면설계서에 대응하는 화면이 없습니다.
근거는 [유저 플로우](USER-FLOW.md) UF-019~UF-023과 UF-030, [워크 플로우](WORKFLOW.md)
WF-019~WF-023과 WF-030, [정보 구조도](IA.md) 2·3절의 이동 'SCR-005 → SCR-003'입니다. 공통 요소는
WU-001에서, 항목 ID 배지와 참조 줄·내보내기 처리는 WU-002에서 정한 것을 그대로 받아 썼습니다.
**이 화면이 그릴 입력은 이 문서가 만든 화면 파일 자체입니다.** 그래서 6절은 `screens/SCR-000.json`의
구조([데이터 규격](../../docs/08-data-spec.md) 4절)를 화면의 요구로 그대로 받았습니다.

### props 표기 규칙

`props`의 키는 블록의 React 컴포넌트 prop 이름을 그대로 씁니다(POL-026, 시스템 규칙). 한글 슬롯
이름은 쓰지 않습니다. 값은 이렇게 적었습니다.

| 값의 모양 | 뜻 | 예 |
| --- | --- | --- |
| 문자열·불리언·숫자 | 화면에 그대로 보이는 값 | `"title": "프로젝트"`, `"showSearch": true` |
| state 키 이름 문자열 | 그 화면 `state`의 값에서 온다 | `"items": "projects"` |
| state 키 이름 문자열(콜백 prop) | 눌렀을 때 그 state 키를 바꾼다 | `"onSelect": "selectedProjectId"` |
| state 키 이름 문자열의 배열 | 묶음 여럿을 차례로 받는다. WU-002에서 처음 썼습니다 | `"groups": ["parentRefs", "childRefs"]` |
| state 키가 아닌 핸들러 이름 | 화면 밖으로 나가거나 다른 화면으로 가는 동작. 이 화면의 state를 바꾸지 않습니다 | `"onSelect": "openPolicyItem"` |
| 문자열의 배열 | 묶음마다 다른 고정 문구. WU-003에서 처음 썼습니다 | `"emptyMessages": ["적힌 디스크립션이 없습니다", "적힌 예외가 없습니다"]` |

## 2. SCR-001 프로젝트 목록

뷰어의 입구입니다. 저장소의 `projects/` 아래 폴더를 읽어 카드로 보여 주고, 카드를 누르면
진행 현황(SCR-002)으로 갑니다.

```json
{
  "id": "SCR-001",
  "refs": ["UF-001", "UF-002", "UF-003", "UF-004", "UF-005", "UF-033", "WF-001~005", "WF-033"],
  "state": { "keyword": "", "projects": [], "selectedProjectId": null }
}
```

| 영역 | 이름 | 블록 | props | 요구사항 | 정책 |
| --- | --- | --- | --- | --- | --- |
| SCR-001-A01 | 글로벌 헤더 | BLK-0001 `^2` | `logo`, `title`, `showBack`, `showSearch`, `actions` | REQ-001, REQ-020 | POL-004, POL-001 |
| SCR-001-A02 | 프로젝트 카드 목록 | BRQ-0001 `^0` (등록 요청) | `items`, `onSelect`, `keyword` | REQ-001, REQ-002, REQ-020 | POL-008, POL-005, POL-004 |
| SCR-001-A03 | 빈 상태 | BLK-0012 `^1` | `illustration`, `title`, `description`, `action` | REQ-001, REQ-019 | POL-008, POL-020 |
| SCR-001-A04 | 바깥으로 나가는 버튼 | BLK-0003 `^2` | `primaryAction`, `secondaryAction`, `disabled` | REQ-004, REQ-015 | POL-003, POL-001 |

**디스크립션에서 짚을 것**

- A01: 입구라 뒤로가기를 두지 않습니다. 검색은 이미 읽어 둔 프로젝트의 **이름만** 거릅니다.
- A02: 카드의 모든 값은 `_meta/status.json`에서 읽습니다. 진행 상태 배지는 POL-005의 다섯 값만
  씁니다. **이 배지의 모양을 여기서 정하고 SCR-002와 뒤의 작업 단위가 그대로 받아 씁니다.**
- A03: A02를 대신해 보입니다. 둘이 같이 보이지 않습니다. 권한이 없어 비어 보이는 경우와 폴더가
  정말 없는 경우를 문구로 구분합니다.
- A04: 주 버튼은 claude.ai/code 세션을, 보조 버튼은 GitHub 저장소를 새 탭으로 엽니다. 뷰어는
  프로젝트를 만들지 않습니다.

**인터랙션**

| 영역 | 트리거 | 바꾸는 state | 결과 |
| --- | --- | --- | --- |
| A01 | 검색어를 입력한다 | `keyword` | A02의 카드를 이름으로 거릅니다. 결과가 없으면 A03이 보입니다. |
| A01 | 우측 액션을 누른다 | 없음 | GitHub 저장소를 새 탭으로 엽니다. |
| A02 | 프로젝트 카드를 누른다 | `selectedProjectId` | SCR-002로 갑니다. |
| A02 | 검색어가 바뀐다 | `keyword` | 이름이 검색어를 품은 카드만 남습니다. |
| A03 | 다음 행동 버튼을 누른다 | 없음 | GitHub 저장소를 새 탭으로 엽니다. |
| A04 | 주 버튼 / 보조 버튼을 누른다 | 없음 | 세션 / GitHub을 새 탭으로 엽니다. |

**예외 상황**

정책에 적힌 예외를 영역의 `exceptions`에 그대로 옮겼습니다(QA-05). 아래는 그 밖에 이 화면에서
더 적은 것입니다.

| 상황 | 화면 | 근거 |
| --- | --- | --- |
| `_meta/status.json`을 읽지 못했다 | 카드 자체는 보이고 진행 상태 자리에만 '읽지 못했습니다'와 경로를 보입니다 | POL-004, UF-035 |
| 검색 결과가 없다 | A03의 제목을 '검색 결과가 없습니다'로 바꾸고 검색어를 지우는 안내를 보입니다 | BLK-0012의 '검색 결과 없음' 변형 |
| 볼 수 있는 프로젝트가 없다 | A03만 보이고 다른 화면으로 가지 않습니다 | POL-008, POL-020, UF-033 |

## 3. SCR-002 프로젝트 진행 현황

한 프로젝트의 지금 상태를 한 화면에서 봅니다. 읽을 산출물을 고르는 허브입니다.

```json
{
  "id": "SCR-002",
  "refs": ["UF-006~UF-011", "UF-034", "UF-035", "WF-006~WF-011", "WF-034", "WF-035"],
  "state": {
    "stages": [], "selectedStage": null, "expandedStage": null,
    "expandedNotice": false, "pullRequests": [], "changeNotice": null
  }
}
```

| 영역 | 이름 | 블록 | props | 요구사항 | 정책 |
| --- | --- | --- | --- | --- | --- |
| SCR-002-A01 | 글로벌 헤더 | BLK-0001 `^2` | `logo`, `title`, `showBack`, `showSearch`, `actions` | REQ-002, REQ-020 | POL-004, POL-001 |
| SCR-002-A02 | 사람을 기다리는 일 알림 줄 | BRQ-0005 `^0` (등록 요청) | `tone`, `title`, `description`, `actionLabel`, `onAction`, `expandable`, `onExpand` | REQ-003, REQ-004 | POL-007, POL-003, POL-002 |
| SCR-002-A03 | 요약 수치 | BRQ-0002 `^0` (등록 요청) | `metrics`, `columns` | REQ-002, REQ-020 | POL-005, POL-004 |
| SCR-002-A04 | 일곱 단계 진행 표시 | BRQ-0003 `^0` (등록 요청) | `steps`, `currentIndex`, `onSelect`, `expandedId` | REQ-002, REQ-003, REQ-005 | POL-006, POL-005, POL-007 |
| SCR-002-A05 | 고른 단계 요약 카드 | BRQ-0004 `^0` (등록 요청) | `summary`, `status`, `links`, `emptyMessage` | REQ-005, REQ-004, REQ-020 | POL-004, POL-003, POL-002 |
| SCR-002-A06 | 열려 있는 PR 목록 | BLK-0013 `^2` | `renderItem`, `loading`, `endMessage`, `showScrollTop` | REQ-004, REQ-016 | POL-002, POL-003 |
| SCR-002-A07 | 변경 영향 알림 줄 | BRQ-0006 `^0` (등록 요청) | `tone`, `title`, `description`, `actionLabel`, `onAction`, `disabled` | REQ-014, REQ-020 | POL-019, POL-004 |

**디스크립션에서 짚을 것**

- A02: 확정 대기·승인 대기·선택 대기를 한 줄로 먼저 보입니다. 둘 이상이면 앞선 단계의 것 하나를
  먼저 보이고 나머지는 펼쳐서 봅니다(POL-007). 승인 버튼이나 실행 버튼을 뷰어에 두지 않습니다.
  **기다리는 일이 하나도 없으면 줄 자체가 사라집니다.** 이 줄만 BRQ-0005를 씁니다.
- A03: 수치 셋(끝난 단계, 검토 중 단계, 만들어진 문서)은 모두 `_meta/status.json`과 폴더의 파일
  목록에서 **센** 값입니다. 비율이나 예상 완료일처럼 저장소에 없는 값은 보이지 않습니다(POL-004).
- A04: 단계 일곱의 순서를 바꾸지 않습니다. 화면설계서 단계는 작업 단위마다 상태를 따로 가지며,
  배지는 가장 뒤처진 작업 단위의 상태를 보이고 펼치면 작업 단위별 상태가 나옵니다.
- A05: '문서 보기'가 어느 화면으로 갈지는 **문서 코드**로 정합니다(WF-011). 문서는 SCR-003,
  플로우는 SCR-004, 화면설계서는 SCR-005, 검증은 SCR-006입니다.
- A06: 이 프로젝트 폴더를 건드리는 열린 PR만 보입니다. 승인은 GitHub에서 합니다.
- A07: `_meta/changes.json`에 승인된 항목의 변경이 있으면 요약 수치 위에 한 줄로 보이고 SCR-007로
  보냅니다. 변경 기록이 없으면 '변경이 없습니다'로 흐리게 보이고 누를 수 없습니다. **변경이 없어도
  줄은 남습니다.** A02와 묶지 않고 **독립된 영역·블록(BRQ-0006)**으로 둡니다. 이 영역의 근거는
  정보 구조도 3절의 이동 `SCR-002 → SCR-007`이고 **유저 플로우에는 대응하는 단계가 없습니다.**
  대응 단계를 플로우에 만들지 않고 이 영역을 따로 그리기로 2026-11-26에 **확정했습니다.**

**인터랙션**

| 영역 | 트리거 | 바꾸는 state | 결과 |
| --- | --- | --- | --- |
| A01 | 뒤로가기·프로젝트 이름을 누른다 | 없음 | SCR-001로 돌아갑니다. |
| A02 | 알림 줄의 링크를 누른다 | 없음 | 승인 대기면 PR을, 확정·실행 대기면 세션을 새 탭으로 엽니다. |
| A02 | '나머지 보기'를 누른다 | `expandedNotice` | 나머지 기다리는 일의 목록을 폅니다. |
| A03 | 수치 하나를 누른다 | `selectedStage` | 그 수치에 든 첫 단계를 골라 A05를 바꿉니다. |
| A04 | 단계를 누른다 | `selectedStage` | A05의 내용이 그 단계로 바뀝니다. |
| A04 | 화면설계서 단계를 펼친다 | `expandedStage` | 작업 단위별 상태 목록을 폅니다. |
| A05 | '문서 보기'를 누른다 | 없음 | 문서 코드에 맞는 화면으로 갑니다. |
| A05 | '실행·수정 요청' / 'PR 보기'를 누른다 | 없음 | 세션 / GitHub PR을 새 탭으로 엽니다. |
| A05 | 다른 단계를 고른다 | `selectedStage` | 카드 내용이 바뀝니다. |
| A06 | PR 항목을 누른다 | 없음 | GitHub PR을 새 탭으로 엽니다. |
| A06 | 목록 끝까지 스크롤한다 | `pullRequests` | 다음 쪽을 이어 붙입니다. 더 없으면 끝 안내를 보입니다. |
| A07 | 알림 줄을 누른다 | `changeNotice` | 변경 영향(SCR-007)으로 갑니다. |

**예외 상황**

정책의 예외를 영역마다 그대로 옮겼습니다. 그 밖에 더 적은 것은 넷입니다.

| 상황 | 화면 | 근거 |
| --- | --- | --- |
| 기다리는 것이 하나도 없다 | A02를 보이지 않고 A03부터 보입니다 | POL-007 |
| 아직 아무 단계도 실행되지 않았다 | 일곱 단계가 모두 '대기'로 보이고 A05는 안내만 보입니다 | POL-005, POL-006 |
| 고른 단계의 파일이 아직 없다 | A05 본문에 '비어 있음'을 보이고 '문서 보기'를 누를 수 없게 둡니다 | POL-003, POL-004, UF-034 |
| 열린 PR이 하나도 없다 | A06에 끝 안내만 보입니다. 빈 상태 블록을 쓰지 않습니다 | BLK-0013의 '끝' 변형 |

## 4. SCR-003 문서 보기

요구사항·정책·정보 구조도처럼 항목 목록으로 읽는 산출물을 항목 단위로 읽습니다. 항목을 고르면
그 항목이 참조하는 상위 항목과 그 항목을 참조하는 하위 항목이 옆에 나오고, 어느 쪽으로든 눌러서
옮겨 갑니다. 참조를 따라 플로우 미리보기(SCR-004)와 화면설계서 뷰어(SCR-005)로 나갑니다.

```json
{
  "id": "SCR-003",
  "refs": ["UF-012", "UF-013", "UF-014", "UF-028", "WF-012", "WF-013", "WF-014", "WF-028"],
  "state": {
    "docs": [], "docCode": "REQ", "items": [], "selectedItemId": null,
    "parentRefs": [], "childRefs": [], "visitedTrail": []
  }
}
```

  참조 패널에서 들어오면** 그 화면의 탭을 열고, 들어온 ID가 영역 ID(`SCR-000-A00`)면 그 영역을
  고른 채로 엽니다. WU-002가 넘긴 사항(9절)에 대한 답입니다.
- A03: 화면 파일의 `areas`를 적힌 순서대로 React 컴포넌트로 그리고, 영역의 `interactions`에 적힌
  것을 눌러 볼 수 있게 합니다. 누르면 `previewState` 안의 키가 바뀌고 결과가 화면에 나타납니다.
  서버 없이 React State로만 돕니다(REQ-017). **블록을 그리지 못한 영역은 건너뛰지 않습니다.**
  그 자리에 '블록을 그리지 못했습니다'와 블록 ID를 보이고 나머지 영역은 그대로 그리며, 그 영역도
  고를 수 있어 디스크립션과 예외는 읽힙니다(POL-014).
- A04: 고른 영역의 디스크립션과 예외를 **접지 않고 나란히** 보입니다(POL-015). 문장은 화면 파일의
  `description`과 `exceptions`를 적힌 순서 그대로이며 뷰어가 요약하지 않습니다. 묶음마다 빈 자리
  문구가 다릅니다('적힌 디스크립션이 없습니다' / '적힌 예외가 없습니다').
- A05: 고른 영역에 걸린 요구사항과 정책을 묶음 둘로 보이고, ID를 누르면 문서 보기(SCR-003)의 그
  항목으로 갑니다. 정보 구조도 3절의 이동 'SCR-005 → SCR-003'이 이 자리입니다. **SCR-003-A04,
  SCR-004-A04와 같은 블록(BRQ-0008)을 씁니다.** 다시 쓴 근거는 7절에 적었습니다.
- A06: 화면이 쓴 블록을 영역마다 한 줄로 보이고 **라이브러리 블록 · 등록 요청 중인 블록 · 알 수
  없는 블록** 셋으로 갈라 보입니다(POL-016). 줄에는 블록 ID와 Major 버전 범위, 그 블록을 쓴 영역이
  있습니다. 줄을 누르면 화면을 옮기지 않고 A03에서 그 영역을 고릅니다. 블록 하나를 자세히 보는
  화면은 뷰어에 없습니다.
- A07: 주 버튼이 PPTX 내보내기입니다. **내보내는 단위는 화면설계서 하나이고 보고 있는 화면 한
  장이 아닙니다.** 화면 한 장이 장표 한 장이고 그려진 화면과 영역별 디스크립션을 같이
  담습니다(REQ-012, WF-022). 그리지 못한 영역도 **비우지 않고 표시해 담습니다**(POL-017).
  보조 버튼은 세션을 엽니다. A06의 알 수 없는 블록을 세션에 알리는 자리이며 유저 플로우의
  이탈(UF-021 → UF-032)이 여기서 일어납니다.
- A08: 내보내기 결과를 A07 아래 한 줄로 보입니다. 상태는 WF-023이 판정한 '내려받음',
  '내보내지 못함', '내보낼 것 없음' 셋이고 누르기 전에는 줄을 보이지 않습니다. **SCR-004-A07과
  같은 블록(BRQ-0010)을 씁니다.**
- A09: A03을 대신해 보입니다. 둘이 같이 보이지 않습니다. 보고 있는 화면 하나가 비어 있어도 A07의
  내보내기는 그대로 둡니다. 화면설계서에 그릴 화면이 하나도 없을 때만 내보내기를 보이지
  않습니다(POL-021). SCR-001-A03, SCR-003-A05, SCR-004-A06과 같은 모양입니다.

## 7. 화면에서 쓰는 UI 블록

Core 가이드, 표준 블록 순으로 찾았습니다(POL-022, 시스템 규칙). 고른 근거는 블록의 "쓰는 상황"과
"쓰지 않을 때"입니다. 쓴 블록 다섯은 모두 `guidance._source`가 `human`이고 `pending_ai_draft`가
`false`라 근거로 쓸 수 있습니다. 폐기된 블록은 쓰지 않았습니다. WU-002와 WU-003에서 쓴 곳을 같은
표에 이어 적었습니다. **WU-003은 새 라이브러리 블록을 한 개도 더하지 않았습니다.** 와이어프레임
렌더링, 영역 하이라이트, 블록 참조 표시처럼 이 화면에만 있는 자리는 커머스 목업 25개에 짝이
없어 등록 요청으로 갔습니다(아래).

#### 알림 줄을 두 블록으로 가른 근거

0.1.0에서는 두 줄이 `tone`과 문구만 다르다고 보아 한 블록(BRQ-0005)을 A02와 A07이 함께 썼습니다.
2026-11-26 사람의 검토에서 **한 블록으로 묶지 않기로 정해** 둘로 갈랐습니다. 쓰임이 이렇게
다릅니다.

| 가르는 기준 | BRQ-0005 대기 알림 줄 (A02) | BRQ-0006 변경 영향 알림 줄 (A07) |
| --- | --- | --- |
| 무엇을 알리는가 | 지금 **사람이 해야 할 일**(확정 대기·승인 대기·선택 대기) | 승인된 항목이 **바뀌었다는 사실**. 할 일이 아닙니다 |
| 누르면 어디로 가는가 | **뷰어 바깥**. GitHub PR이나 claude.ai 세션을 새 탭으로 엽니다. 화면은 그대로 남습니다 | **뷰어 안**. 변경 영향(SCR-007)으로 화면을 옮깁니다 |
| 언제 보이고 사라지는가 | 기다리는 일이 있을 때만 나타나고 **없으면 줄 자체가 사라집니다** | **늘 자리를 지킵니다.** 변경이 없으면 '변경이 없습니다'로 흐리게 남고 누를 수 없습니다 |
| 몇 건을 담는가 | 여럿. 앞선 단계의 것 하나를 머리로 보이고 나머지를 **펼쳐서** 봅니다 | 한 건. 펼침이 없습니다 |
| 그래서 필요한 prop | `expandable`, `onExpand` | `disabled` |
| 근거 | POL-007, REQ-003 | POL-019, REQ-014 |

접힘·펼침을 가진 목록형 줄과, 비활성 상태로 남는 단건 줄은 상태 기계가 다릅니다. 한 블록으로
묶으면 어느 쪽에도 안 쓰는 prop이 절반씩 남습니다. 그래서 블록을 둘로 둡니다.

#### BRQ-0008을 영역 셋이 함께 쓰는 근거

WU-001의 검토에서 **쓰임이 다르면 번호를 공유하지 말라**고 정했습니다. 반대로 쓰임이 같으면
재사용하는 것이 맞습니다. BRQ-0008은 SCR-003-A04와 SCR-004-A04가 함께 쓰고, WU-003에서
SCR-005-A05가 더해졌습니다. 가르는 기준을 BRQ-0005·BRQ-0006 때와 똑같이 대어 보았더니 세 자리의
모든 칸이 같았습니다.

| 가르는 기준 | SCR-003-A04 항목 참조 패널 | SCR-004-A04 분기 정책 목록 | SCR-005-A05 영역 요구사항·정책 목록 |
| --- | --- | --- | --- |
| 무엇을 담는가 | ID 배지가 붙은 줄의 묶음(상위·하위) | ID 배지가 붙은 줄의 묶음(분기의 연결) | ID 배지가 붙은 줄의 묶음(영역에 걸린 요구사항·정책) |
| 누르면 어디로 가는가 | 그 ID가 가리키는 항목으로. 종류에 따라 같은 화면 안이거나 SCR-004·SCR-005 | 그 ID가 가리키는 항목으로. 정책이므로 SCR-003 | 그 ID가 가리키는 항목으로. 요구사항·정책이므로 SCR-003 |
| 언제 보이는가 | 무언가(항목)를 고르면 그 옆에 나타납니다 | 무언가(분기 노드)를 고르면 그 옆에 나타납니다 | 무언가(영역)를 고르면 그 옆에 나타납니다 |
| 이동할 수 없는 줄 | 끊긴 참조. 누를 수 없고 안내를 함께 보입니다(POL-011) | '정책 없음'과 끊긴 정책 ID. 누를 수 없고 안내를 함께 보입니다(POL-011, POL-012) | 끊긴 요구사항·정책 ID. 누를 수 없고 안내를 함께 보입니다(POL-011) |

한쪽에만 쓰이고 다른 쪽에 남는 prop이 없습니다. 상태 기계도 '이동할 수 있음 / 이동할 수 없음'
하나로 같습니다. 블록을 가르면 같은 것을 두세 번 만들게 되고, 화면들이 서로를 오가는데 줄의
모양이 어긋납니다. [정보 구조도](IA.md) 6절이 WU-002를 한 작업 단위로 묶은 근거가 "두 화면이
같은 '항목 ID와 참조 이동' 요소를 공유한다"인데, **그 공유되는 요소가 바로 이 블록입니다.**
SCR-005-A05는 그 요소를 세 번째로 쓰는 자리입니다. 빈 자리 문구만 POL-015를 따라
'걸린 정책이 없습니다'로 둡니다. 문구는 값이지 prop이 아니라 블록을 가를 까닭이 되지 않습니다.
